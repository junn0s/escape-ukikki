# 제작 로드맵

> 문서 버전: 1.1
> 목표: 문서 기준선을 실제 플레이 가능한 Unity MVP로 전환

---

## 1. 제작 전략

이 프로젝트의 가장 큰 위험은 아트가 아니라 온라인 동기화, 괴물 AI와 게임 상태의 결합이다. 따라서 순서는 다음 원칙을 따른다.

1. 두 실행 파일이 연결되는 것을 가장 먼저 확인한다.
2. 캡슐과 회색 박스로 전체 한 판을 먼저 완주한다.
3. 서버 판정과 동시 사건을 아트보다 먼저 고정한다.
4. 6인 테스트를 마지막까지 미루지 않는다.
5. 핵심 루프가 검증된 뒤 에셋을 교체한다.
6. 일정 부족 시 콘텐츠 종류를 줄이고 시스템 연결은 유지한다.

---

## 2. 핵심 경로

```text
Unity 프로젝트
→ 세션·로비
→ 네트워크 플레이어
→ 그레이박스 맵
→ 서버 라운드 상태
→ 괴물과 소음
→ 미션·진행률
→ 빌런 강화
→ 감염·해독제
→ 회의·승패
→ 6인 안정화
→ 아트·오디오·시연
```

이 경로에 없는 작업은 핵심 경로가 안정되기 전 우선하지 않는다.

## 3. M0 — 프로젝트 기반

### 작업

- Unity 6.3 LTS URP 프로젝트 생성
- Git, `.gitignore`, Git LFS 설정
- 폴더와 Assembly Definition 구성
- Input System 설정
- Bootstrap, MainMenu, Lobby, Laboratory 씬 생성
- 기본 CI 또는 수동 빌드 체크리스트
- Balance ScriptableObject 기본값 입력

### 완료 조건

- 빈 Windows Development Build가 실행된다.
- 씬 전환이 된다.
- 팀 전원이 같은 Unity 버전으로 프로젝트를 연다.
- 저장소에 Library 등 생성물이 들어가지 않는다.

## 4. M1 — 로컬 버티컬 슬라이스

### 작업

- 플레이어 2D 이동과 직교 탑다운 카메라
- 벽 단면과 2D 충돌 처리
- 3개 방 회색 박스
- 상호작용 프레임워크
- 퓨즈 미션 한 종
- 괴물 한 마리 2D 웨이포인트 그래프 순찰
- 미션 실패 소음과 괴물 조사
- 물기와 로컬 감염 타이머

### 완료 조건

한 명이 이동해 미션을 실패하고, 소리를 들은 괴물을 피해 도망치며, 물리면 감염되는 흐름이 로컬에서 작동한다.

이 단계에서 재미와 카메라 가독성이 형편없으면 네트워크 콘텐츠를 늘리기 전에 수정한다.

## 5. M2 — 네트워크 기반

### 작업

- Unity Services 초기화와 익명 인증
- MPS Session + Relay 방 생성·참가

- 역할 개인 전송
- 연결 종료 기본 처리

### 완료 조건

- 서로 이동하고 같은 미션 스테이션을 본다.
- 한 명만 스테이션을 점유한다.
- 역할 정보가 자기 화면에만 보인다.

## 6. M3 — 라운드 핵심 시스템

### 작업

- 전체 라운드 상태 머신
- 30초 보호와 15분 타이머
- 10개 방 그레이박스
- 플레이어 시작점 6개
- 괴물 4마리 서버 AI
- 소음 우선순위와 6초 가속
- 원형 근접 감지·소음 현장 급습·물기
- 미션 배정과 개인 20% 기여
- 프로젝트 25/50/75/100 단계
- 기본 결과 화면

### 완료 조건

- 6명이 회색 박스 맵에서 미션으로 100%를 만들 수 있다.
- 괴물 AI와 감염 결과가 전원에게 일치한다.
- 15분 시간 초과와 프로젝트 승리가 모두 발생한다.

---

## 7. M4 — 빌런과 사회 시스템

### 작업

- 빌런 가짜 미션
- 강화 3축 × 2단계
- 4→6→8마리 생성
- 스피커 지도와 45초 쿨타임
- 영구 단서 4종
- CCTV와 서버 로그
- 회의 호출·채팅·투표
- 퇴출과 유령
- 동시 승패 우선순위

### 완료 조건

- 빌런이 프로젝트 게이지를 올리지 않고 위장한다.
- 생존자가 단서를 보고 회의에서 투표한다.
- 빌런·생존자 퇴출 결과가 정확하다.
- 유령 미션과 현실 생존자 0명 판정이 작동한다.

## 8. M5 — 감염 경제와 콘텐츠

### 작업

- 백신실 중앙 제어 PC 2대, 배합 코드 발급
- 백신실 제작대 2대, 코드 입력과 합성, 선점
- 소지 한도 1개
- 90/60/30초 독성 단계, 감염 중 이동 속도 감소
- 해독제 사용과 재감염
- 미션 UI 4종 완성
- 10개 방 미션 스테이션 분배

### 완료 조건

- 물린 뒤 백신실에 도달해 배합을 마치는 전략이 실제로 가능하다.
- 빌런도 해독제를 제작하거나 선점할 수 있다.
- 모든 미션과 아이템 요청이 네트워크에서 중복되지 않는다.

## 9. M6 — 아트·UI·오디오 적용

### 작업

- 소리 없이도 핵심 상태를 알 수 있고, 화면을 보지 않아도 괴물 접근을 어느 정도 판단할 수 있다.

## 11. 팀 역할 권장

### 3인 팀

| 역할 | 책임 |
| --- | --- |
| 개발 A | 네트워크, 세션, 라운드, 승패 |
| 개발 B | 플레이어, AI, 미션, 감염 |
| 디자인·아트 | 레벨, UI, 에셋, 오디오, QA 지원 |

### 4~6인 팀

| 역할 | 책임 |
| --- | --- |
| 테크 리드 | 아키텍처, 네트워크, 통합 |
| 게임플레이 개발 | 플레이어, 미션, 감염, 빌런 |
| AI·레벨 개발 | 괴물, 2D 경로 그래프, 맵 |
| UI·UX | 전체 화면과 미니게임 |
| 2D·테크 아트 | 스프라이트, 애니메이션, 레이어, VFX |
| 기획·QA·오디오 | 밸런스, 테스트, 사운드, 발표 |

인원이 적으면 역할을 합치되 네트워크 통합 책임자는 한 명으로 명확히 둔다.

## 12. 작업 단위

각 작업은 다음을 포함한다.

```text
목적
사용자 관점 결과
기술 범위
완료 조건
테스트 방법
관련 문서
담당자
```

예:

```text
제목: 미션 실패 소음을 괴물이 추적한다
완료 조건:
- 서버가 Medium 소음을 생성한다.
- 30m 경로 반경 내 괴물이 반응한다.
- 가장 가까운 소리를 선택한다.
- 최대 6초간 6m/s로 이동한다.
- Host+Client에서 동일하게 보인다.
```

## 13. 통합 규칙

- 매일 또는 짧은 작업 주기마다 `main`에서 실행 가능한 빌드를 유지한다.
- 네트워크 프리팹과 씬은 담당자 외 변경을 최소화한다.
- 기능 브랜치는 작게 유지한다.
- 큰 기능은 아트 없이 먼저 병합하고 표현은 후속 작업으로 분리한다.
- 패키지, ProjectSettings, 입력 설정 변경은 사전에 공유한다.
- P0 버그가 있으면 신규 기능을 중단한다.

## 14. 컷라인

일정이 부족할 때 다음 순서로 제거한다.

1. 헬기 상세 연출
2. 캐릭터 액세서리와 환경 장식
3. 상세 결과 타임라인
4. 실시간 CCTV를 이동 로그로 대체
5. 지도 상세 기능
6. 미션 4종 중 한 종
7. 백신실 PC·제작대 사이 차폐 프롭 연출

마지막까지 유지:

- 네트워크 한 판 완주
- 소음과 괴물
- 빌런의 간접 조작
- 단서와 회의
- 승패

감염·해독제가 일정상 완성되지 못하면 시스템 전체를 어설프게 남기기보다 시연 빌드에서 비활성화하고 핵심 루프 완성도를 지킨다. 단, 최종 MVP 목표에는 포함한다.

## 15. 위험 관리

| 위험 | 영향 | 조기 신호 | 대응 |
| --- | --- | --- | --- |
| 6인 네트워크 지연 | 전체 진행 불가 | 2인에서도 중복·끊김 | M2를 최우선, 매 단계 실제 빌드 테스트 |
| 괴물 8마리 끼임 | 불공정 사망 | 문 앞 정지·겹침 | 맵 폭, 회피, AI 복구를 함께 수정 |
| 어둠으로 가독성 저하 | 미션·길 찾기 불가 | 테스터가 계속 벽에 충돌 | 환경 기본광과 실루엣 확보 |
| 빌런이 너무 쉽게 발각 | 역할 재미 상실 | 첫 회의 반복 퇴출 | 괴물 위장 추격, 단서 정보량 조정 |
| 빌런이 추리 불가능 | 생존자 무력감 | 근거 없는 투표 | 단서, CCTV, 로그 가독성 강화 |
| 백신실 배합이 무의미 | 시스템 사용 안 함 | 첫 감염 전 경기 종료 | 백신실 동선과 코드 발급 피드백 조정 |
| 회의로 경기 과도 연장 | 시연 실패 | 20분 이상 반복 | 최대 3회, 데모 프로필 시간 단축 |
| 외부 서비스 장애 | 심사 접속 실패 | Relay 오류 | 동일 PC 데모, 로컬 모드, 녹화 영상 |
| 아트 작업 과투자 | 시스템 미완성 | 맵 확정 전 프롭 증가 | 그레이박스 승인 뒤 제작 |

## 16. 해커톤 시연 구성

### 2~3분 시연 순서

1. 연구소와 역할 소개
2. 생존자 미션 실패로 소음 발생
3. 괴물의 6초 가속과 추격
4. 빌런이 다른 방 스피커 작동
5. 강화 후 붉은 연기 또는 격리실 개방
6. 현장 단서를 보고 회의 호출
7. 투표 또는 프로젝트 100%로 결과

정상 15분 판을 발표 시간 안에 압축하기 위해 Demo 프로필에서 진행률과 쿨타임을 조절한다. 정상 게임 규칙과 다른 값임을 발표 자료에 표시한다.

## 17. 최종 완료 정의

- GDD의 모든 MVP 규칙이 구현돼 있다.
- 참가 코드로 6명이 접속한다.
- 생존자와 빌런 양쪽으로 승리 가능하다.
- 소음→괴물→빌런 조작→단서→회의의 연결이 한 판에 나타난다.
- 연속 3판을 치명적 오류 없이 마친다.
- 최종 Windows 빌드, 실행 안내, 라이선스 고지와 백업 영상이 있다.
- 문서, 코드, 밸런스 데이터와 빌드 버전이 서로 일치한다.
