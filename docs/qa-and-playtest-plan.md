# QA·플레이 테스트 계획

> 문서 버전: 1.5
> 기준: GDD 1.5, MVP 1.5

---

## 1. 품질 목표

- 6명이 한 판을 시작하고 끝낼 수 있다.
- 역할·미션·투표 정보가 잘못된 대상에게 노출되지 않는다.
- 네트워크 지연에도 중복 판정이 없다.
- 괴물이 끼어 게임을 막지 않는다.
- 모든 승패와 동시 사건의 결과가 재현 가능하다.
- 핵심 소리와 단서를 처음 플레이한 이용자가 이해한다.

---

## 2. 테스트 환경

### 2.1 기본 구성

- Unity Editor Host + Editor Client
- Windows Development Build Host + Client
- 서로 다른 PC의 Host + 5 Clients
- 동일 PC의 Multiplayer Play Mode

### 2.2 네트워크 조건

| 프로필 | 지연 | 패킷 손실 | 목적 |
| --- | ---: | ---: | --- |
| 정상 | 20~50ms | 0% | 기본 |
| 일반 인터넷 | 100ms | 1% | 목표 환경 |
| 불안정 | 200ms | 3% | 복구와 중복 판정 |
| 단절 | 임의 | 100% | 재접속·종료 |

### 2.3 성능 조건

- 기준 PC 사양을 팀이 한 대 지정한다.
- 호스트가 가장 큰 CPU 부하를 받으므로 Host 빌드에서 우선 측정한다.
- 4마리와 8마리 상태를 각각 측정한다.

## 3. 빌드 스모크 테스트

매 빌드에서 다음 순서만큼은 확인한다.

1. 게임 실행
2. 익명 인증 성공
3. 방 생성과 코드 표시
4. 클라이언트 참가
5. 준비와 시작
6. 역할 공개
7. 이동과 상호작용
8. 미션 한 개 완료
9. 괴물 소리 반응
10. 회의와 투표
11. 강제 승패
12. 결과 후 로비 복귀

하나라도 실패하면 시연 후보 빌드로 표시하지 않는다.

### 3.1 서비스 부팅 자동 검사

- Unity Services 초기화가 익명 인증보다 먼저 호출되는지 확인한다.
- 이미 초기화·로그인된 상태에서는 SDK 호출을 반복하지 않는지 확인한다.
- 초기화 또는 인증 실패 시 메인 메뉴로 진행하지 않고 실패 상태와 사용자 메시지를 남기는지 확인한다.
- `00_Bootstrap` 씬에 `BootstrapEntryPoint`, `UnityServicesInitializer`, 상태 화면이 모두 연결됐는지 확인한다.
- 실제 Cloud 연결 후 재생에서는 익명 인증 성공과 Player ID 존재를 확인하되 토큰은 로그에 출력하지 않는다.

### 3.2 방 생성·참가 자동 검사

- 방 생성 요청이 최대 6명·비공개·Relay 옵션으로 전달되는지 확인한다.
- 참가 코드의 앞뒤 공백 제거와 대문자 정규화 후 SDK에 전달되는지 확인한다.
- 빈 참가 코드는 SDK를 호출하지 않고 사용자 오류로 처리하는지 확인한다.
- 생성·참가 버튼을 연속 입력해도 진행 중인 SDK 요청이 하나만 실행되는지 확인한다.
- 성공 시 세션 ID·참가 코드·호스트 여부를 읽기 모델에 반영하는지 확인한다.
- 코드 만료·참가 불가·인증·Relay 실패를 구분한 사용자 메시지를 표시하는지 확인한다.
- `01_MainMenu` 씬에 `NetworkManager`, `UnityTransport`, `GameSessionController`와 세션 화면이
  올바르게 연결됐는지 확인한다.
- 실제 Cloud 환경에서는 호스트 방 생성과 참가 코드 발급을 확인하고 테스트 종료 시
  `ISession.LeaveAsync()`로 세션을 정리한다.
- 완료 판정은 Multiplayer Play Mode 또는 별도 빌드로 Host+Client 2개 인스턴스가 같은 참가
  코드에 접속한 뒤에만 한다.

### 3.3 Host+Client Relay 통합 검사

1. `Tools > Monkey Lab > Configure Host Client Play Mode`를 실행한다.
2. 상단 시나리오가 `HostClient2`인지 확인하고 상단 재생 버튼으로 실행한다.
3. Main Editor와 Player 2가 모두 `Running`이면
   `Tools > Monkey Lab > Test Host Client Relay`를 실행한다.
4. 로그에서 같은 Relay 코드, `players=2/6`, Player 2의 2번 슬롯·노랑·비호스트를 확인한다.
5. 테스트 세션이 자동 삭제되고 오류 로그가 남지 않아야 통과한다.

Play Mode Scenario는 재생 단축키 대신 Unity 상단 재생 버튼으로 시작한다.

## 9. 1차 플레이 테스트: 로컬 핵심 루프

참가자 2~4명, 빌런과 회의 없이 진행한다.

확인 질문:

- 미션 실패로 소리가 났음을 이해하는가?
- 괴물이 왜 방향을 바꿨는지 이해하는가?
- 코너와 우회로로 피할 수 있는가?
- 어둡지만 방과 오브젝트를 읽을 수 있는가?
- 2D 탑다운 화면에서 벽 단면·프롭·캐릭터가 겹쳐 읽기 어렵지 않은가?

통과 기준:

- 원인 불명 감염 응답 20% 이하
- 괴물 끼임 0건
- 참가자 대부분이 지도 없이 세 개 이상의 방을 구분

---

## 10. 2차 플레이 테스트: 빌런과 추리

6명, 스피커·강화·단서·회의를 포함한다.

확인 질문:

- 빌런이 정상 미션처럼 위장할 수 있는가?
- 생존자가 단서를 실제로 발견하는가?
- 단서가 확정 증거가 아니라 토론 근거가 되는가?
- 스피커가 확정 처치가 아닌 유도로 느껴지는가?
- 회의에서 방, 시간, 목격에 대한 구체적인 대화가 생기는가?

통과 기준:

- 최소 한 번 이상 회의 발생
- 판마다 강화 단서 한 개 이상 발견
- 빌런이 항상 첫 회의에 퇴출되거나 끝까지 절대 의심받는 양극단을 피함

---

## 11. 3차 플레이 테스트: 전체 경제

감염, 배합 코드, 제작, 선점, 유령과 모든 승패를 포함한다.

확인 질문:

- 3분 제작이 전략적 준비로 이해되는가?
- 해독제 선점이 추리와 협력 대화를 만드는가?
- 30초 최종 독성이 사전 준비로 대응 가능한가?
- 사망 후 미션이 충분히 참여감을 주는가?
- 잘못 퇴출된 생존자의 손해가 적절한가?
- 15분 제한이 긴장감과 완주 가능성을 함께 주는가?

## 12. 플레이 후 설문

1~5점:

- 괴물이 왜 움직였는지 이해할 수 있었다.
- 소음을 낼 때 긴장됐다.
- 어두운 맵에서도 길과 상호작용을 찾을 수 있었다.
- 생존자로 추리할 근거가 충분했다.
- 빌런으로 속이는 과정이 재미있었다.
- 감염과 해독제가 공정했다.
- 회의 시간이 적절했다.
- 사망 후에도 할 일이 있었다.
- 다시 플레이하고 싶다.

자유 응답:

- 가장 재미있었던 순간은?
- 가장 억울했던 순간은?
- 이해하기 어려운 규칙은?
- 빌런을 의심하게 만든 결정적 근거는?
- 제거해도 될 것 같은 기능은?

## 13. 버그 우선순위

| 우선순위 | 기준 | 예시 |
| --- | --- | --- |
| P0 | 진행 불가, 데이터·역할 노출 | 접속 불가, 승패 미발생, 역할 전원 공개 |
| P1 | 핵심 기능 오작동 | 괴물 정지, 미션 중복, 투표 오류 |
| P2 | 우회 가능한 기능 문제 | 특정 UI 겹침, 일부 소리 누락 |
| P3 | 미관·낮은 영향 | 장식 위치, 작은 애니메이션 문제 |

P0는 새 기능보다 먼저 수정한다. P1이 남아 있으면 시연 후보 빌드로 승격하지 않는다.
