# 원숭이 괴물 탈출 게임 — 제작 문서

> 문서 세트 버전: 2.0  
> 기준일: 2026-07-30 (GDD 2.0 — 2D 전환)

이 디렉터리는 기획부터 Unity 구현, 에셋 제작, 테스트와 해커톤 데모까지 필요한 기준 문서를 모은다.

## 문서 우선순위

규칙이나 수치가 충돌하면 다음 순서로 판단한다.

1. `game-design-document.md`: 게임의 의도, 역할, 핵심 규칙, 승패
2. `system-design-document.md`: 규칙의 상세 상태와 예외 처리
3. `technical-design-document.md`: Unity 및 네트워크 구현 방식
4. `balance-and-telemetry.md`: 초기 수치와 조정 기준
5. 나머지 제작 문서

밸런스 수치는 플레이 테스트로 조정할 수 있지만, 역할 구성과 승리 구조는 GDD 변경 없이 바꾸지 않는다.

## 역할별 읽기 순서

최종 게임 기획서는 모든 역할이 먼저 읽는다. 이후 순서는 아래를 따른다.

| 역할 | 순서 |
| --- | --- |
| 기획·PM | MVP 범위 → 제작 로드맵 → 밸런스·텔레메트리 |
| 개발 | 시스템 설계서 → 기술 설계서 → 프로젝트 구조 → QA·플레이 테스트 |
| 레벨·UI·아트·오디오 | 맵·레벨 설계서 → UI·UX 설계서 → 아트·오디오 에셋 가이드 |

## 변경 절차

1. 변경 이유와 영향을 확인한다.
2. GDD의 확정 규칙 변경인지, 밸런스 값 변경인지 구분한다.
3. 최상위 문서를 먼저 수정한다.
4. 관련 설계서와 테스트 항목을 함께 수정한다.
5. 구현 코드와 ScriptableObject 값을 마지막에 반영한다.

문서에는 `최종`, `진짜최종`, `수정본` 같은 파일명을 추가하지 않는다. Git 이력과 문서 버전을 사용한다.
