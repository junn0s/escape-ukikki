# 개발 현황

> 갱신일: 2026-07-31
> 기준 문서: `production-roadmap.md`, `game-design-document.md`, `technical-design-document.md`

이 문서는 기획 변경을 위한 문서가 아니라, 설계 문서가 Unity 프로젝트에 어디까지 반영됐는지 기록하는 작업 현황표다.

## 현재 단계

- M0 프로젝트 기반: 완료
- M1 로컬 버티컬 슬라이스: 완료
- M2 네트워크 기반: 구현 완료 — Host+Client 최종 수동 검증 대기
- M3 라운드 핵심 시스템: 구현 완료 — Host+Client 완료 조건 수동 검증 대기
- M4 빌런과 사회 시스템: 강화 3축, 현장 단서 4종, 스피커 리모컨, 빌런 가짜 미션,
  회의·투표·퇴출 구현 완료 — Host+Client 수동 검증 대기. CCTV·서버 로그와 유령 이동은 시작 전
- M5 이후: 시작 전

## 이번 구현 완료

### 플레이어와 카메라

- `WASD` 이동
- 마우스 위치를 향한 캐릭터 회전
- 회전하지 않는 직교 투영 2D 탑다운 추적 카메라
- `Rigidbody2D`·`CapsuleCollider2D` 기반 벽 충돌
- 플레이어·바이저·손전등 범위를 분리한 2D 스프라이트 표현
- `F`로 2D 손전등 범위 켜기·끄기

### 맵과 상호작용

- 연구소 10개 방과 복도를 XY 평면의 2D 스프라이트 맵으로 전환
- 방별 바닥 색·한글 표지와 벽 단면·통로 출입구 `Collider2D` 생성
- 기존 3D 프리미티브와 원근 쿼터뷰 오브젝트 제거
- 6개 시작점 중 첫 번째 위치에 로컬 플레이어 배치
- 거리 기반 상호작용 대상 탐색
- 화면 하단 `E` 상호작용 안내
- 전력 복구실·보안실·액체 보관실·실험실 A에 M3 회색상자 미션 스테이션 5개 배치
- 퓨즈·차단기·CCTV·시료 분류 4종을 유형별 색·문구로 구분하고 공통 3단계 순서 입력으로 검증
- 잘못된 퓨즈 선택 시 즉시 실패하고 다시 상호작용해 재시도
- 성공 시 스테이션 표시등과 본체 색상 복구
- 수행 중 캐릭터와 스테이션이 전원 화면에서 점멸하고, 완료 순간 2.5초간 공개 완료 색상 표시
- 개인별 완료 색상은 해당 소유자에게만 유지하고 전체 누적 결과는 프로젝트 HUD로 공개
- 미션 중 이동·조준 잠금, `Esc` 취소 후 입력 복구
- 퓨즈 오답 1회마다 `Medium` 소음 사건 1회 발행
- 미션 실패 소음은 2D 그래프 경로 거리 30m까지 전달하며, 배치된 괴물 4마리 중 범위 안의 모든 개체가 각자 반응하고 실제 스파크 효과음도 재생

### 소음과 괴물 AI

- 시작 후 30초 동안 괴물은 순찰만 하고 소음 조사·추격·물기 비활성화
- 방 중심 10개와 연결 14개로 구성한 서버용 2D 웨이포인트 그래프
- 외곽 시작점에서 각자 독립된 3개 방 경로를 순찰하는 프로토타입 원숭이 4마리 배치
- 평상시 순찰 경로는 분산하고, 같은 소음 반경에 든 괴물의 현장 집결은 의도된 반응으로 유지
- 순찰 속도 2.6m/s, 방 체류 6±1초
- 소음 조사 시작 속도 6.0m/s, 최대 가속 6초 후 순찰 속도로 감속
- 소음 지점 도착 후 3초 탐색하고 다시 순찰
- 경로 거리, 소음 크기, 최신 시각, 작은 `noiseId` 순서의 결정적 우선순위 적용
- 평상시 방향과 무관한 원형 근접 감지 2.3/3.1/4.1m 안의 접근 가능한 플레이어 추격
- 소음 위치 도착 시 반경 8m 안의 접근 가능한 플레이어를 조사 속도로 급습
- 괴물 수 4/6/8, 감염 제한 90/60/30초를 `SO_MonsterTier_Default`에 연결
- 추격 속도 4.6m/s, 표적 상실 시 마지막 위치에서 3초 수색
- 콜라이더 표면 간 0.9m 안에서 물리 장애물을 재검사하고 0.35초 준비 후 물기 판정
- 물기 후 1.2초 재행동, 피격자에게 1.5초 재물림 보호 적용
- 소음 발생 배너와 상태별 프로토타입 색상 표시

### 감염과 해독제 사용 기반

- 생존자가 물리면 당시 독성 단계에 따라 90/60/30초 감염 즉시 시작
- 감염 시작 시 제한시간을 고정하고 이후 독성 강화나 재물림으로 초기화하지 않음
- 회의 연결을 위한 감염 타이머 정지·재개 인터페이스 준비
- 타이머 0에서 `DeadGhost` 상태로 전환하고 괴물 감지 대상에서 제외
- 감염 중에는 괴물이 동료로 인식해 감지·추격·물기하지 않고, 해독 후 다시 감지
- 감염 HUD에 남은 시간, 해독제 보유 여부와 사용 진행률 표시
- `R`로 1.5초 사용, 이동 입력 시 취소·미소비, 완료 시 한 개 소비 후 치료
- 소지 한도 1개를 `SO_AntidoteBalance_Default`에 연결
- 해독제 레시피·제작기·획득·보관은 M5 범위이며 현재 일반 플레이에서는 시작 소지품을 지급하지 않음

### 온라인 서비스 시작 기반

- `00_Bootstrap`에서 Unity Services 초기화 후 익명 인증을 순서대로 실행
- 중복 초기화 요청은 같은 작업을 공유하고, 이미 로그인된 세션은 SDK 재호출 없이 재사용
- 인증 성공 후 Player ID가 존재할 때만 다음 씬으로 전환
- 실패 시 Bootstrap에 머물며 사용자용 오류와 `다시 시도` 버튼 표시
- Unity Cloud 프로젝트 미연결 상태는 SDK 호출 전에 감지하고 연결 위치 안내
- Bootstrap 전용 카메라로 편집기와 빌드에서 오류 안내 화면을 동일하게 표시

### MPS Session과 Relay

- `01_MainMenu`에 `NetworkManager`, `UnityTransport`, `GameSessionController` 구성
- 호스트 포함 최대 6명의 비공개 MPS Session을 Relay 네트워크로 생성
- 참가 코드의 공백 제거·대문자 정규화 후 코드 참가
- 생성·참가 중 연속 입력은 같은 진행 작업을 공유해 SDK 중복 호출 방지
- 성공 시 참가 코드, 현재 인원, 최대 인원, 호스트 여부 표시
- 빈 코드, 만료 코드, 참가 불가, 인증, Relay, 요청 제한 오류를 사용자 문장으로 구분
- 일반 참가자는 `LeaveAsync`, 호스트는 `DeleteAsync`로 종료해 호스트 이전을 사용하지 않음
- 에디터 메뉴에서 실제 Relay 방 생성·삭제를 반복 검증할 수 있는 도구 제공
- 서버 권위 `LobbyRosterService`가 6개 슬롯·6색·준비 상태와 시작 가능 여부를 판정
- `LobbyRosterNetwork`가 참가자 공개 상태를 `NetworkList`로 복제하고 색상·준비 요청을 서버에서 재검증
- 중복 색상은 거부하며, 일반 시작은 호스트·6명·전원 준비 조건을 모두 만족해야 허용
- 메인 메뉴에 6개 참가 슬롯, 호스트 표시, 색상 선택과 준비·해제 버튼 연결
- `HostClient2` Multiplayer Play Mode 시나리오와 Relay 2인 자동 검증·정리 도구 제공
- 호스트의 서버 판정 시작 요청과 NGO `10_Laboratory` 동시 씬 전환 연결
- 연결 참가자마다 유지되는 `P_Player_Network` Player NetworkObject 생성
- 로비 슬롯별 시작점·색상 복제와 소유자 입력·카메라, 위치·방향 동기화 연결
- 네트워크 플레이어 프리팹도 `Rigidbody2D`·`CapsuleCollider2D`와 XY 위치·Z 회전 동기화로 전환
- 온라인 연구소에서는 로컬 중복 플레이어만 비활성화하고 미션·소음·괴물 시스템 루트는 유지
- 네트워크 소유자에게 `PlayerInteractor`를 활성화해 `E` 상호작용 연결
- 6개 네트워크 시작점을 현재 2D 맵의 실제 방 중심 좌표로 동기화
- 네트워크 소유자의 조준 카메라를 연구소 카메라로 재결합하고 물기 알림·감염 HUD 연결
- 라운드 상태 갱신 때 같은 카메라 대상을 재설정하지 않아 온라인 이동 화면의 주기적 끊김 제거
- 온라인 소유자의 `PlayerInteractor`를 하단 `E` 상호작용 안내에 다시 연결
- 서버가 소유권·요청 순서·1.5m 거리·벽 경로를 검사한 뒤 퓨즈 미션 시작 승인
- 퓨즈 스테이션 독점 점유와 10초 무입력·이동·연결 종료 자동 해제
- 개인별 완료 상태 서버 판정과 같은 플레이어의 재완료 요청 차단
- 서버 무작위 빌런 1명 배정과 소유자 전용 역할 값·5초 개인 역할 표시

### M3 라운드 핵심 시스템 기반

- 서버 권위 `RoleReveal → GracePeriod → Exploration → RoundResult` 상태 머신
- 역할 공개 5초, 시작 보호 30초, 탐색 900초를 `SO_RoundBalance_Default`에 연결
- 서버 시계·프로젝트 포인트·25/50/75/100% 단계·결과를 전원에게 복제
- 문서 우선순위대로 빌런 퇴출 → 프로젝트 100% → 진짜 생존자 0명 → 시간 만료 승패 판정
- 소유자 전용 개인 미션 목록과 완료 상태, 생존자당 5개·2,000점(20%) 배정
- 플레이어 시작 위치에서 가까운 스테이션부터 개인 미션 순서를 결정하고 같은 거리에서는
  네트워크 ID로 순서를 고정
- 다섯 생존자가 각자 5개 회색상자 스테이션을 완료하면 내부 총점 10,000점 도달
- 프로젝트 진행도·개인 미션 수·결과를 표시하는 기본 HUD
- 호스트 개발 검증용 탐색 즉시 시작·진행도 25% 추가·제한시간 5초 버튼
- 괴물 AI는 서버에서만 실행하고 상태와 XY 위치를 클라이언트에 복제
- 감염 판정과 타이머는 서버에서만 진행하고 공개 생명 상태와 소유자 타이머를 복제
- 네트워크 퓨즈 실패는 서버 `NoiseService`로 전달되어 서버 괴물 전체가 같은 사건에 반응
- M3 회색상자는 퓨즈 1·차단기 1·CCTV 1·시료 분류 2개로 구성하며, 전용 타이밍·채널·
  분류 조작은 M5의 미션 UI 4종 완성 범위

### M4 빌런 강화 3축

- `ScentLevel`·`PopulationLevel`·`ToxicityLevel`을 0~2 단계 정수로 보관하는 서버 권위 상태
- 후각(실험실 B)·개체(보안실)·독성(백신실 B)에 축별 강화 스테이션 1개씩 배치
- 강화 미션은 12~18초 채널링이며 취소·이탈 시 즉시 초기화
- 서버가 빌런 역할·축 상단·라운드 단계·거리·순서 번호를 모두 재검증한 뒤에만 단계 증가
- 강화 단계는 브로드캐스트하지 않고 빌런 소유 클라이언트에게만 Rpc로 전달
- 후각 강화는 원형 근접 감지 반경을 2.3m → 3.1m → 4.1m로 적용
- 개체 강화는 격리실 A(1단계)·격리실 B(2단계)에서 두 마리씩 3초 예고 후 활성화해 4 → 6 → 8마리
- 독성 강화는 새 감염에만 90초 → 60초 → 30초를 적용하고 진행 중인 감염 타이머는 유지
- 배치된 괴물 수가 `SO_MonsterTier`의 4/6/8과 어긋나면 씬 검증과 테스트가 실패
- 빌런 화면 우측 상단에만 축별 현재 단계를 표시

### M4 현장 단서 4종

- 후각 강화 → 실험실 환풍구의 붉은 연기, 개체 강화 → 격리실 파손된 잠금장치,
  독성 강화 → 백신실 바닥의 빈 주사기
- 축마다 2회 강화가 가능하므로 종류별 마커를 2개씩 두고 두 번째 강화는 다른 방에 남긴다
- 단서는 라운드 종료까지 사라지지 않는다. 자동 소멸 타이머를 두지 않는다
- 조사해도 단서는 유지되며, 조사 여부는 결과 통계용으로만 구분한다
- 단서 상태는 `NetworkList`로 복제해 중간 참가·재접속 클라이언트도 기존 단서를 본다
- 단서에 "누가 남겼는지"는 담지 않는다

### M4 스피커 리모컨

- 빌런 전용 지도에서 10개 방 중 하나를 골라 그 방의 스피커를 울린다
- 서버가 역할·생존·라운드 단계·방 존재·쿨타임을 재검증한 뒤 승인한다
- 승인 시 해당 방에서 `Large`(40m 경로 거리) 소음 사건 1개를 발행한다
- 3초 재생은 연출이며 소음 사건 ID는 하나만 쓴다
- 45초 공용 쿨타임은 서버 시각으로 판정하고, 남은 시간은 빌런 본인에게만 보낸다
  (생존자가 쿨타임을 보면 스피커를 누른 시각을 역산할 수 있다)
- 사용한 방의 스피커에 붉은 LED가 남아 단서 4종이 완성된다
- 시작 보호 시간과 회의 중에는 사용할 수 없고, 사망한 빌런도 사용할 수 없다
- 누가 눌렀는지는 로그에 남기지 않는다

### M4 빌런 가짜 미션

- 빌런도 생존자와 같은 방식·같은 개수로 개인 미션 목록을 받는다
- 스테이션 상호작용, 점유, 완료 연출이 생존자와 동일해 겉보기로 구분되지 않는다
- 완료해도 프로젝트 진행률은 오르지 않는다(GDD 9.1)
- 서버가 역할로 완료 경로를 나눈다. 빌런은 `ServerTryCompleteFakeMission`으로 가고
  이 경로는 `ProjectProgressService`를 아예 호출하지 않는다
- `ServerTryCompleteMission`의 생존자 검사가 마지막 방어선으로 남아 있어,
  경로 분기가 잘못돼도 진행률은 오르지 않는다
- 생존자 5명만으로 내부 총점 10,000점에 도달하므로 빌런 참여 여부가 승패에 영향을 주지 않는다

### M4 회의·투표·퇴출

- `RoundPhase`에 `MeetingDiscussion`·`MeetingVote`·`MeetingResult` 3단계 추가
- 회의 중에는 탐색 타이머가 멈춘다. 단계 타이머만 흐른다(GDD 16.2)
- 기존 `AllowsPlayerControl`·`AllowsMissionInteraction`이 탐색 단계만 허용하므로
  이동·미션·강화·스피커가 회의 중 자동으로 차단된다
- 호출 검증: 탐색 단계, 살아 있는 호출자, 첫 회의 120초 잠금, 공용 쿨타임 120초, 최대 3회
- 동시 호출은 서버가 먼저 받은 유효 요청 하나만 승인한다
- 토론 90초 → 투표 30초 → 결과 5초, 전원 투표 완료 시 남은 시간을 기다리지 않는다
- 표는 투표 중에 공개하지 않고 진행 수(`n/m`)만 보여준다
- 집계: 마지막 표만 유효, 자기 투표 허용, 미투표는 기권 처리,
  단독 최다만 퇴출, 동률·기권 최다는 무퇴출
- 빌런 퇴출 시 `isVillainExiled`가 켜지고 즉시 생존자 승리로 판정된다
  (기존 `RoundWinConditionService`의 우선순위를 그대로 사용)
- 생존자 퇴출 시 유령이 되어 괴물 감지 대상에서 빠진다
- 퇴출된 플레이어의 역할은 라운드 종료 전까지 공개하지 않는다(GDD 16.4)

## 직접 실행 방법

1. 2D 생성 파일이 없거나 맵을 재생성할 때만 `Tools > Monkey Lab > Build Complete 2D Top Down`을 실행한다.
2. 온라인 흐름은 Unity에서 `Assets/_Project/Scenes/00_Bootstrap.unity`를 열고 재생한다.
3. 메인 메뉴에서 `방 만들기` 또는 참가 코드 입력 후 `코드로 참가`를 누른다.
4. 호스트는 6명 준비 후 `게임 시작`, 개발 검증은 `개발용 현재 인원 시작`을 누른다.
5. 연구소에서 각자 다른 슬롯·색상으로 생성되고 자기 캐릭터만 이동하는지 확인한다.
6. 2인 검증은 `Tools > Monkey Lab > Configure Host Client Play Mode`를 한 번 실행하고,
   상단 시나리오가 `HostClient2`인지 확인한 뒤 상단 재생 버튼을 누른다.
7. 로컬 게임플레이는 `Assets/_Project/Scenes/10_Laboratory.unity`를 열고 재생한다.
8. 화면 상단의 시작 보호 30초 동안 괴물이 순찰만 하는지 확인한다.
9. 보호 종료 후 원숭이의 짧은 원형 근접 범위에 들어가 밝은 빨간색 추격 상태를 확인한다.
10. 원숭이가 가까워지면 흰색 물기 상태와 피격 배너가 표시되고, 물기 성공 뒤 순찰로 복귀한다.
11. 물리면 우측 하단에 감염 타이머와 해독제 보유 상태가 표시된다.
12. 전력 복구실의 주황색 퓨즈 스테이션 가까이에서 `E`를 누른다.
13. 일부러 틀린 퓨즈를 눌러 소음 배너와 원숭이의 노란색 조사 상태를 확인한다. 조사 중에는
   현장 도착 시 소음 위치 반경 8m 안에 있으면 밝은 빨간색 급습 추격으로 바뀐다.
14. 원숭이는 소음 지점에서 보라색 탐색 상태를 거친 뒤 다시 순찰한다.
15. 해독 흐름은 새 재생에서 `Tools > Monkey Lab > Test Infection And Antidote`로 확인한다.
16. `Esc`로 미션을 취소하거나 `F`로 손전등을 켜고 끈다.
17. 강화는 빌런으로 배정된 인스턴스에서 실험실 B·백신실 B·입원실의 보라색 스테이션에
   `E`로 접근해 확인한다. 채널링 중 `Esc`나 이탈로 즉시 초기화되는지도 함께 본다.
18. 개체 강화 성공 시 격리실 A에서 3초 경고 후 두 마리가 추가되는지 확인한다.
19. 강화 성공 후 해당 방(실험실 B·격리실 A·백신실 B)에 단서가 나타나고, 라운드가 끝날 때까지
   사라지지 않는지 확인한다. 단서는 생존자 화면에서도 보여야 한다.
20. 빌런 화면 우측의 `스피커 지도 열기`로 방을 고르면 그 방 스피커가 3초간 노란색으로 켜지고,
   반경 40m 안의 괴물이 모두 조사 상태로 전환되는지 확인한다.
21. 스피커 사용 후 그 방 스피커 옆에 붉은 LED가 남고, 45초 쿨타임이 빌런 화면에만
   표시되는지 확인한다.
22. 탐색 120초 이후 좌측 하단 `회의 호출`을 누르면 토론 90초 → 투표 30초 → 결과 5초를
   거쳐 탐색으로 돌아오는지 확인한다.
23. 회의 중에는 상단 탐색 타이머가 멈추고 이동·미션·강화·스피커가 모두 막히는지 확인한다.
24. 전원이 투표를 마치면 남은 시간을 기다리지 않고 결과로 넘어가는지 확인한다.
25. 개발 검증에서 빌런을 퇴출하면 즉시 생존자 승리로 라운드가 끝나는지 확인한다.

`RoundWinConditionService`는 이미 SDD 16.1의 우선순위(빌런 퇴출 → 진행률 100% →
현실 생존자 0명 → 시간 만료)를 그대로 구현하고 있다. 다만 `NetworkRoundState`가
`isVillainExiled`를 항상 `false`로 넘기고 있어, 투표·퇴출을 구현해야 실제로 동작한다.
동시 승패 우선순위를 새로 만들지 말고 이 입력만 연결한다.

M1 완료 조건인 이동, 미션 실패, 소음 조사, 괴물 추격·물기와 로컬 감염 흐름은 연결됐다.
M2의 인증, Relay Host+Client 2개 인스턴스 참가와 로비 공개 상태 동기화를 실제 Cloud에서
검증했다. M3의 서버 라운드·진행도·괴물·감염 동기화, 4종 회색상자와 결과 화면까지
구현했다. M4는 빌런 강화 3축, 현장 단서 4종, 스피커 리모컨, 빌런 가짜 미션, 회의·투표·퇴출까지
구현했으며, CCTV·서버 로그와 유령 이동은 아직 시작하지 않았다.

회의 단계에서는 탐색 타이머가 멈추고 이동·미션·강화·스피커가 모두 차단된다. 다만 감염
타이머와 해독제 제작 정지는 아직 연결하지 않았다(SDD 4장 상태표). 유령은 현재 이동 제약과
채팅이 없어 퇴출 후 관전만 가능하다.
