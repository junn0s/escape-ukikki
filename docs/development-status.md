# 개발 현황

> 갱신일: 2026-08-08
> 기준 문서: `production-roadmap.md`, `game-design-document.md`, `technical-design-document.md`

이 문서는 기획 변경을 위한 문서가 아니라, 설계 문서가 Unity 프로젝트에 어디까지 반영됐는지 기록하는 작업 현황표다.

## 현재 단계

- M0 프로젝트 기반: 완료
- M1 로컬 버티컬 슬라이스: 완료
- M2 네트워크 기반: 구현 완료 — Host+Client 최종 수동 검증 대기
- M3 라운드 핵심 시스템: 구현 완료 — Host+Client 완료 조건 수동 검증 대기
- M4 빌런과 사회 시스템: 구현 완료 — Host+Client 수동 검증 대기
- M5 감염 경제와 콘텐츠: 해독제 경제·생존자 22종·빌런 6종·난이도별 4~5개 배정 구현
- M6 통합: 유령 채팅·월드 조명·실시간 CCTV·엔딩·Windows 빌드 코드 완료, 실행 검증 대기

## 이번 구현 완료

### 플레이어와 카메라

- `WASD` 이동
- 캐릭터 몸통은 회전하지 않는다. 마우스 방향으로 도는 것은 손전등을 매단 `AimPivot`뿐이다
- 이동 방향에 따른 좌우 플립 (어몽어스식 측면 프로필)
- 이동 거리 기반 걷기 프레임 순환(`CharacterWalkAnimator`). 플레이어와 괴물이 함께 쓰며
  걷기 그림이 들어오기 전까지는 정지 프레임만 표시한다 (아트 가이드 §2.2)
- 회전하지 않는 직교 투영 2D 탑다운 추적 카메라
- 이동 방향 선행, 물림·실패 위치 흔들림과 원격 플레이어까지 동일한 절차형 보행 바운스
- `Rigidbody2D`·`CapsuleCollider2D` 기반 벽 충돌
- 플레이어·바이저·손전등 범위를 분리한 2D 스프라이트 표현
- `F`로 2D 손전등 범위 켜기·끄기, 소등 시 실루엣용 밝기 0.6%·반경 0.5m만 유지
- 54도 손전등 원뿔을 벽·닫힌 문·정적 장애물 충돌 지점에서 잘라 인접 방으로 새지 않게 처리
- 실효 약 7% 전역광과 전용 2D Renderer를 사용해 0% 단계 월드 시야를 벽 윤곽과
  54도 손전등 원뿔로 제한

### 맵과 상호작용

- 연구소 10개 방과 복도를 XY 평면의 2D 스프라이트 맵으로 전환
- 방별 바닥 색·한글 표지와 벽 단면·통로 출입구 `Collider2D` 생성
- 회색상자 표현을 절차적 스프라이트로 교체: 방·복도 바닥 2m 타일 반복, 벽·프롭 몸체 9-slice,
  프롭 카테고리 표식 9종. 크기가 달라도 이음새·외곽선 두께가 일정하다 (아트 가이드 §4.1.1)
- 기존 3D 프리미티브와 원근 쿼터뷰 오브젝트 제거
- 6개 시작점 중 첫 번째 위치에 로컬 플레이어 배치
- 거리 기반 상호작용 대상 탐색
- 화면 하단 `E` 상호작용 안내
- 현재 방 진입 배너·마우스 조준점·월드 상호작용 모서리 표식·하단 조작 도움말
- 서버 추적 대상일 때만 나타나는 붉은 화면 가장자리 맥동과 미션·단계 통합 사건 배너
- 미션 예약 구역을 확보한 방별 전용 프롭 87개, 공용 설비 40개, 벽체·코너·통행선 100개를 교체 가능한
  `EnvironmentPropSlot`으로 배치하고 프리팹 교체 기준점·장착 유형·정렬 순서 기록
- 긴 복도 약 4m 간격 유도등·벽 설비 덕트·굴절 방향 표식과 고유 출입구 자동문 27개 배치
- 자동문은 서버가 플레이어·괴물 접근을 감지하고 패널 애니메이션·충돌 상태를 전원 동기화
- 자동문 프레임 상태등은 닫힘·이동 중·열림을 청록·주황·초록으로 구분
- 전체 월드 스프라이트를 URP 2D Lit 재질로 전환하고 0/25/50/75/100% 조명 단계를 실제 광원으로 연결
- 25%에는 방별 부분 조명·표지판, 50%에는 보안실, 75%에는 탈출 경로, 100%에는 최종 출구를 완전 점등 대비 최대 15%로 점등
- 구형 회색상자 미션 스테이션 10개와 비상 배터리 수신기를 제거하고 신규 미션 전용 공간 확보
- 생존자 22종·빌런 6종·해독제 장치를 방별 전용 스테이션으로 분산
- 백신실 A/B의 데이터 다운로드·주사기 폐기·냉동고 온도·샘플 스캔과 중앙 제어 PC·해독제
  제작대를 최종 장비 스프라이트로 교체하고, 상호작용 외곽선과 기존 서버 권위 판정을 유지
- 실험실 A의 슬라이드 세척·RGB 시약 분류·배양통 오염 장치와 실험실 B의 현미경·플라스크
  충전·쥐 케이지를 방별 콘셉트가 다른 최종 장비 스프라이트로 교체하고 서버 권위 판정을 유지
- 격리실 A/B의 배선·압력·제독·필터·역류 장치를 방공호 제독 설비와 화학 공장 HVAC라는
  서로 다른 최종 장비 스프라이트로 교체하고 흰 안개·서버 권위 판정 연결을 유지
- 입원실의 수액·바이탈·투약 기록 파쇄 장치와 액체 보관실의 공유 밸브·폐기물 압축기를
  야전병원과 지하 제약 공장 콘셉트의 최종 장비 스프라이트로 교체하고 서버 권위 판정을 유지
- 드래그, 타이밍 클릭·키 입력, 2단계 선택, 월드 운반, 원형 회전, 회로 클릭 회전,
  방향키 조율과 문자열 키 입력을 각각 서버 입력 단위로 검증
- 잘못된 퓨즈 선택 시 즉시 실패하고 다시 상호작용해 재시도
- 성공 시 스테이션 표시등과 본체 색상 복구
- 수행 중 캐릭터와 스테이션이 전원 화면에서 점멸하고, 완료 순간 2.5초간 공개 완료 색상 표시
- 개인별 완료 색상은 해당 소유자에게만 유지하고 전체 누적 결과는 프로젝트 HUD로 공개
- 미션 중 이동·조준 잠금, `Esc` 취소 후 입력 복구
- 퓨즈 오답 1회마다 `Medium` 소음 사건 1회 발행
- 미션 실패 소음은 2D 그래프 경로 거리 30m까지 전달하며, 배치된 괴물 4마리 중 범위 안의 모든 개체가 각자 반응하고 실제 스파크 효과음도 재생

### 소음과 괴물 AI

- 시작 후 30초 동안 괴물은 순찰만 하고 소음 조사·추격·물기 비활성화
- 방 중심 10개, 문 안쪽 접근 노드, 중앙 가로·세로 통행 축과 연결 14개로 구성한
  서버용 2D 웨이포인트 그래프
- 외곽 시작점의 원숭이 4마리는 활성 개체들의 방 후보를 공유하고 최근 3곳 기억·8m 목적지
  예약·타 개체와의 최대 거리 점수로 비어 있는 구역을 동적 순찰
- 이동 중 2.2m 분리 조향과 소음 현장 분산 도착으로 같은 경로·한 점 포개짐을 억제하고,
  2초 막힘 시 최대 3회 현재 목적지 경로를 재계산
- 평상시 순찰 경로는 분산하고, 같은 소음 반경에 든 괴물의 현장 포위는 의도된 반응으로 유지
- 순찰 속도 2.6m/s, 방 체류 6±1초
- 일반 소음 조사 시작 속도 6.0m/s, 최대 가속 6초 후 순찰 속도로 감속
- 일반 소음 지점 도착 후 5초 탐색하고 다시 순찰
- 경로 거리, 소음 크기, 최신 시각, 작은 `noiseId` 순서의 결정적 우선순위 적용
- 접근 가능한 플레이어를 콜라이더 표면 간 원형 근접 감지 1.25/1.75/2.25m에서 추격. 손전등과 이동 여부는
  감지 조건이 아니다 (GDD 1.6)
- 반경 밖으로 벗어나면 표적을 잃고 마지막 위치를 수색
- 미션 실패·스피커 강제 급습은 범위 안의 모든 괴물이 기존 추격·물기 준비보다 우선하며,
  현장 도착 전 다른 표적으로 새지 않고 도착 후 각각 5.33m·8m 안의 대상을 급습
- 강제 소음 현장 도착 후 해당 반경을 10초간 유지하며 소음원 주변 경로 지점을 빠르게 배회
- 괴물 수 4/6/8, 감염 제한 90/60/30초를 `SO_MonsterTier_Default`에 연결
- 추격 속도 4.6m/s, 표적 상실 시 마지막 위치에서 5초 수색
- 콜라이더 표면 간 0.2m 안에서 물리 장애물을 재검사하고 0.35초 준비 후 물기 판정
- 물기 후 1.2초 재행동, 피격자에게 1.5초 재물림 보호 적용
- 소음 발생 배너와 상태별 프로토타입 색상 표시

### 감염과 해독제 사용 기반

- 생존자가 물리면 당시 독성 단계에 따라 90/60/30초 감염 즉시 시작
- 감염 시작 시 제한시간을 고정하고 이후 독성 강화나 재물림으로 초기화하지 않음
- 회의 연결을 위한 감염 타이머 정지·재개 인터페이스 준비
- 타이머 0에서 `DeadGhost` 상태로 전환하고 괴물 감지 대상에서 제외
- 감염 중에는 괴물이 동료로 인식해 감지·추격·물기하지 않고, 해독 후 다시 감지
- 감염 중에는 이동 속도가 `SO_PlayerMovement_Default`의 배율(0.8)만큼 감소
- 감염 HUD에 남은 시간, 해독제 보유 여부, 사용 진행률과 백신실 이동·코드 확인 안내 표시
- `R`로 1.5초 사용, 이동 입력 시 취소·미소비, 완료 시 한 개 소비 후 치료
- 소지 한도 1개를 `SO_AntidoteBalance_Default`에 연결
- 배합 코드·제작대 시스템은 M5 범위이며 현재 일반 플레이에서는 시작 소지품을 지급하지 않음

### 온라인 서비스 시작 기반

- `00_Bootstrap`에서 Unity Services 초기화 후 익명 인증을 순서대로 실행
- 중복 초기화 요청은 같은 작업을 공유하고, 이미 로그인된 세션은 SDK 재호출 없이 재사용
- 인증 성공 후 Player ID가 존재할 때만 다음 씬으로 전환
- 실패 시 Bootstrap에 머물며 사용자용 오류와 `다시 시도` 버튼 표시
- Unity Cloud 프로젝트 미연결 상태는 SDK 호출 전에 감지하고 연결 위치 안내
- Bootstrap 전용 카메라로 편집기와 빌드에서 오류 안내 화면을 동일하게 표시

### MPS Session과 Relay

- `01_MainMenu`에 `NetworkManager`, `UnityTransport`, `GameSessionController` 구성
- 호스트 포함 최대 6명의 비공개 MPS Session을 Relay 네트워크로 생성
- 참가 코드의 공백 제거·대문자 정규화 후 코드 참가
- 생성·참가 중 연속 입력은 같은 진행 작업을 공유해 SDK 중복 호출 방지
- 성공 시 참가 코드, 현재 인원, 최대 인원, 호스트 여부 표시
- 빈 코드, 만료 코드, 참가 불가, 인증, Relay, 요청 제한 오류를 사용자 문장으로 구분
- 일반 참가자는 `LeaveAsync`, 호스트는 `DeleteAsync`로 종료해 호스트 이전을 사용하지 않음
- 에디터 메뉴에서 실제 Relay 방 생성·삭제를 반복 검증할 수 있는 도구 제공
- 서버 권위 `LobbyRosterService`가 6개 슬롯·6색·준비 상태와 시작 가능 여부를 판정
- `LobbyRosterNetwork`가 참가자 공개 상태를 `NetworkList`로 복제하고 색상·준비 요청을 서버에서 재검증
- 중복 색상은 거부하며, 일반 시작은 호스트·6명·전원 준비 조건을 모두 만족해야 허용
- 메인 메뉴에 6개 참가 슬롯, 호스트 표시, 색상 선택과 준비·해제 버튼 연결
- `HostClient2` Multiplayer Play Mode 시나리오와 Relay 2인 자동 검증·정리 도구 제공
- 호스트의 서버 판정 시작 요청과 NGO `10_Laboratory` 동시 씬 전환 연결
- 연결 참가자마다 유지되는 `P_Player_Network` Player NetworkObject 생성
- 로비 슬롯별 시작점·색상 복제와 소유자 입력·카메라, 위치·방향 동기화 연결
- 네트워크 플레이어 프리팹도 `Rigidbody2D`·`CapsuleCollider2D`와 XY 위치·Z 회전 동기화로 전환
- 온라인 연구소에서는 로컬 중복 플레이어만 비활성화하고 미션·소음·괴물 시스템 루트는 유지
- 네트워크 소유자에게 `PlayerInteractor`를 활성화해 `E` 상호작용 연결
- 6개 네트워크 시작점을 현재 2D 맵의 실제 방 중심 좌표로 동기화
- 네트워크 소유자의 조준 카메라를 연구소 카메라로 재결합하고 물기 알림·감염 HUD 연결
- 라운드 상태 갱신 때 같은 카메라 대상을 재설정하지 않아 온라인 이동 화면의 주기적 끊김 제거
- 온라인 소유자의 `PlayerInteractor`를 하단 `E` 상호작용 안내에 다시 연결
- 서버가 소유권·요청 순서·1.5m 거리·벽 경로를 검사한 뒤 퓨즈 미션 시작 승인
- 신규 미션의 역할·개인 배정·거리·중복 완료를 공통 서버 권위 계층에서 차단
- 서버 무작위 빌런 1명 배정과 소유자 전용 역할 값·7초 개인 역할 표시

### M3 라운드 핵심 시스템 기반

- 서버 권위 `RoleReveal → GracePeriod → Exploration → RoundResult` 상태 머신
- 역할 공개 7초, 시작 보호 30초, 탐색 900초를 `SO_RoundBalance_Default`에 연결
- 서버 시계·프로젝트 포인트·25/50/75/100% 단계·결과를 전원에게 복제
- 문서 우선순위대로 빌런 퇴출 → 프로젝트 100% → 진짜 생존자 0명 → 시간 만료 승패 판정
- 소유자 전용 개인 미션 목록과 완료 상태, 생존자당 4~5개·2,000점(20%) 배정
- 플레이어 시작 위치·난이도·조작 종류를 기준으로 고정 카탈로그 ID 미션을 정렬하고,
  같은 라운드에서는 한 스테이션을 한 생존자에게만 배정
- 다섯 생존자가 배정 미션을 완료하면 내부 총점 10,000점 도달
- 프로젝트 진행도·개인 미션 수·결과를 표시하는 기본 HUD
- 호스트 F10 개발 패널에서 탐색 시작, 프로젝트 0/25/50/75/100%, 남은 시간,
  강제 승패, 대상별 역할·감염·치료·유령·해독제와 강화 3축을 서버 권위로 조작
- 괴물별 복제 상태·목표 client ID를 표시하고 마지막 소음의 경로 반경을 월드 원으로 시각화
- 개발 패널은 에디터·Development 빌드에서만 열리고 Release 빌드에서는 자동 비활성화
- 괴물 AI는 서버에서만 실행하고 상태와 XY 위치를 클라이언트에 복제
- 감염 판정과 타이머는 서버에서만 진행하고 공개 생명 상태와 소유자 타이머를 복제
- 10개 방의 생존자 미션 22종과 별도 해독제 배합 2종을 고정 카탈로그 ID로 관리

### M4 빌런 전용 미션 누적 강화

- `VillainMissionKind` 6종 중 서버가 4종을 무작위 배정하고 배정·완료 마스크를 서버 권위로 보관
- 배정 목록과 누적 완료 단계는 브로드캐스트하지 않고 빌런 소유 클라이언트에만 지정 Rpc로 전달
- 실험실 A·격리실 B·입원실·액체 보관실·중앙 보안 광장·전력 복구실에 위장 미션 배치
- 각 서버 권위 컴포넌트가 역할·배정 여부·중복 완료·라운드 단계·상호작용 거리를 재검증
- 완료 1·2회는 3초 예고 후 괴물을 두 마리씩 추가해 4 → 6 → 8마리
- 완료 3회는 새 감염 제한시간을 60초 → 40초로 낮추고 진행 중인 감염 타이머는 유지
- 완료 4회는 원형 근접 감지 반경을 1.25m → 1.75m로 확대
- 배치된 괴물 수가 `SO_MonsterTier`의 4/6/8과 어긋나면 씬 검증과 테스트가 실패
- 빌런 화면 우측 상단에는 누적 단계와 실제 개체·독성·감지 효과를 표시

### M4 현장 단서 4종

- 완료한 빌런 미션 종류에 맞춰 붉은 연기·파손 잠금장치·파쇄 기록·누출 냉각수·절단 CCTV·
  절단 전력선 흔적을 해당 방에 남긴다
- 단서는 라운드 종료까지 사라지지 않는다. 자동 소멸 타이머를 두지 않는다
- 조사해도 단서는 유지되며, 조사 여부는 결과 통계용으로만 구분한다
- 단서 상태는 `NetworkList`로 복제해 중간 참가·재접속 클라이언트도 기존 단서를 본다
- 단서에 "누가 남겼는지"는 담지 않는다
- 강화 완료 순간에는 마커를 서버에 예약만 하고, 7m 안의 살아 있는 생존자가 전부 떠난
  뒤에 익명 흔적으로 공개한다. 빌런·유령은 공개를 막지 않으며 보류 상태는 복제하지 않는다

### M4 스피커 리모컨

- 빌런 전용 지도에서 10개 방 중 하나를 골라 그 방의 스피커를 울린다
- 서버가 역할·생존·라운드 단계·방 존재·쿨타임을 재검증한 뒤 승인한다
- 승인 시 해당 방에서 `Large`(40m 경로 거리) 소음 사건 1개를 발행한다
- 3초 재생은 연출이며 소음 사건 ID는 하나만 쓴다
- 45초 공용 쿨타임은 서버 시각으로 판정하고, 남은 시간은 빌런 본인에게만 보낸다
  (생존자가 쿨타임을 보면 스피커를 누른 시각을 역산할 수 있다)
- 사용한 방의 스피커에 붉은 LED가 남아 단서 4종이 완성된다
- 시작 보호 시간과 회의 중에는 사용할 수 없고, 사망한 빌런도 사용할 수 없다
- 누가 눌렀는지는 로그에 남기지 않는다

### M4 빌런 가짜 미션

- 빌런도 위장 판정을 위해 시민 미션 데이터를 받지만 본인 HUD에는 빌런 전용 작전만 표시한다
- 빌런도 퓨즈·차단기·CCTV·시료·배터리·밸브·회로·안테나·로그의 실제 9종 조작을 끝까지 수행한다
- 스테이션 상호작용, 점유, 완료 연출이 생존자와 동일해 겉보기로 구분되지 않는다
- 완료해도 프로젝트 진행률은 오르지 않는다(GDD 9.1)
- 서버가 역할로 완료 경로를 나눈다. 빌런은 `ServerTryCompleteFakeMission`으로 가고
  이 경로는 `ProjectProgressService`를 아예 호출하지 않는다
- `ServerTryCompleteMission`의 생존자 검사가 마지막 방어선으로 남아 있어,
  경로 분기가 잘못돼도 진행률은 오르지 않는다
- 생존자 5명만으로 내부 총점 10,000점에 도달하므로 빌런 참여 여부가 승패에 영향을 주지 않는다

### M4 회의·투표·퇴출

- `RoundPhase`에 `MeetingDiscussion`·`MeetingVote`·`MeetingResult` 3단계 추가
- 회의 중에는 탐색 타이머가 멈춘다. 단계 타이머만 흐른다(GDD 16.2)
- 기존 `AllowsPlayerControl`·`AllowsMissionInteraction`이 탐색 단계만 허용하므로
  이동·미션·강화·스피커가 회의 중 자동으로 차단된다
- 호출 검증: 탐색 단계, 살아 있는 호출자, 첫 회의 120초 잠금, 공용 쿨타임 120초, 최대 3회
- 동시 호출은 서버가 먼저 받은 유효 요청 하나만 승인한다
- 토론 90초 → 투표 30초 → 결과 5초, 전원 투표 완료 시 남은 시간을 기다리지 않는다
- 표는 투표 중에 공개하지 않고 진행 수(`n/m`)만 보여준다
- 집계: 마지막 표만 유효, 자기 투표 허용, 미투표는 기권 처리,
  단독 최다만 퇴출, 동률·기권 최다는 무퇴출
- 빌런 퇴출 시 `isVillainExiled`가 켜지고 즉시 생존자 승리로 판정된다
  (기존 `RoundWinConditionService`의 우선순위를 그대로 사용)
- 생존자 퇴출 시 유령이 되어 괴물 감지 대상에서 빠진다
- 퇴출된 플레이어의 역할은 라운드 종료 전까지 공개하지 않는다(GDD 16.4)
- 회의 중에는 감염 타이머도 정지하고 남은 값을 보존한다(SDD 4장 상태표)
- 스피커 쿨타임도 회의 중 정지한다. 서버 시각 기준이라 멈춘 시간만큼 완료 시각을 밀어
  남은 값을 보존한다(GDD 16.2)

### M4 토론 채팅

- 토론 단계에서만 열린다. 탐색 중 일반 채팅은 MVP 범위가 아니다(GDD 16.2)
- `NetworkList`로 전원에게 복제하지 않고 살아 있는 참가자에게만 대상 지정 Rpc로 보낸다.
  유령·퇴출자는 전송 대상에서 빠지므로 채팅이 메모리에도 쌓이지 않는다(SDD 11.5, GDD 17)
- 서버가 각괄호를 제거해 Rich Text 태그 삽입과 사칭을 막는다(QA 문서 §280)
- 줄바꿈·연속 공백을 공백 하나로 접고 80자에서 자른다
- 같은 플레이어의 연속 전송은 1초 간격으로 제한한다. 첫 발언은 간격 검사를 받지 않는다
- 회의가 새로 열리면 이전 회의 발언을 비운다
- 메시지 원문은 로그에 남기지 않는다(밸런스 §11). 서버는 개수만 센다
- 최대 글자·전송 간격·보관 메시지 수를 `SO_RoundBalance_Default`에 연결

### M4 유령

- 감염 사망 또는 회의 퇴출로 유령이 된다
- 유령은 콜라이더를 트리거로 바꿔 벽을 통과하지만 실제 바닥 외곽 2m의 결계 밖으로는 나갈 수 없다
- 유령 이동 속도는 4.8m/s로 살아 있을 때보다 빠르다
- 살아 있는 플레이어는 유령을 볼 수 없고, 유령끼리는 반투명으로 보인다
- 유령은 괴물 감지 대상에서 빠진다
- 유령은 강화 스테이션·스피커·회의 호출·투표를 쓸 수 없다
- 유령의 개인 미션 완료는 프로젝트 진행률에 그대로 반영된다(GDD 17)
- 유령 채팅은 생존자 회의 채팅과 별도 Rpc 채널로 나뉘며, 서버가
  `DeadGhost`와 전송 간격을 검증한 뒤 현재 유령에게만 원문을 전달한다

### M4 CCTV와 서버 로그

- 프로젝트 50%(`SecurityAccess`) 도달 사건으로 서버가 단말기를 활성화한다
- 스피커 작동은 잠금 여부와 무관하게 계속 기록되고, 잠금은 열람만 막는다
- 로그에는 작동 시각과 방만 남기고 누가 눌렀는지는 남기지 않는다(GDD 13.1)
- 로그는 `NetworkList`로 복제해 중간 참가·재접속에서도 같은 기록을 본다
- 유령은 단말기를 조작할 수 없다
- 보안실 월드 단말기에서 서버 점유 승인 후 복도·교차로 7개 채널을
  실시간 `RenderTexture`로 전환하며, 현재 채널 하나만 렌더한다

### M5 해독제 경제 — 긴급 배합으로 재설계 (2026-08-07)

- 개인 레시피 탐색을 없애고, 백신실 A/B의 중앙 제어 PC에서 즉석으로 5자리 배합 코드를
  발급받는 방식으로 전환했다(GDD 14.2)
- 코드는 요청자에게만 RPC로 전달하고 서버 `NetworkVariable`에도 소유자 전용 권한으로만
  보관한다. 저장되는 값일 뿐 화면에 남기지 않는 건 클라이언트 표시 로직의 책임이다
- 제작 기회는 무제한이다. 물릴 때마다 다시 PC에서 코드를 받아 제작대에서 배합할 수 있다
- 백신실 A/B에 중앙 제어 PC 1대, 제작대 1대씩 방 반대편에 배치한다(map-level-design 7.2)
- 제작대는 `Idle → AwaitingCode → Synthesizing → Ready → Idle` 순서로 전이한다.
  코드 정답 입력 뒤 합성 4초가 지나면 `Ready`가 되고, 자리를 떠나도 진행된다
- 코드 오입은 입력만 초기화하고, 3회 누적되면 코드를 무효화해 PC에서 다시 받게 한다.
  오입은 소음을 만들지 않는다 — 감염 중 이동 속도 감소가 이미 시간 압박으로 작동한다
- 빌런도 역할 검사 없이 코드를 발급받고 제작할 수 있다. 백신실 출입 자체가 의심 근거가
  되면 위장이 성립하지 않기 때문이다(GDD 14.3)
- 완성품은 선착순 서버 판정이다. 소지 칸을 먼저 확보한 뒤 제작대를 비워 유실을 막는다
- 소지 한도 1개를 서버 권위 `NetworkVariable`로 관리하고 소유자에게만 복제한다
- 해독제 사용은 소유자가 1.5초 채널링을 마친 뒤 서버가 감염·소지 상태를 재검증해 확정한다
- 지정 보관 칸을 제거했다. 즉석 제작이 가능해지면서 비축할 이유가 없어졌고, 감염 사망 시
  소지 해독제와 보유 코드는 그대로 소멸한다(SDD 13.3)
- 유령은 PC·제작대를 조작할 수 없다(GDD 17)
- 감염 중 이동 속도 배율(0.8)을 `SO_PlayerMovement_Default`에,
  분석 시간·코드 길이·최대 오입·합성 시간을 `SO_AntidoteBalance_Default`에,
  아이템 획득 거리 1.2m를 `SO_InteractionBalance_Default`에 연결

### 라운드 마무리와 연결 종료

- 회의가 끝나 탐색이 재개될 때 살아 있는 전원에게 2초 물기 보호를 준다.
  `PostMeetingBiteProtectionSeconds`가 그동안 SO에만 있고 쓰이지 않았다(밸런스 2장, QA 4.9)
- 결과 화면에서 호스트가 `로비로 돌아가기`를 누르면 `01_MainMenu`로 네트워크 씬 전환한다.
  이 경로가 없어 "연속 3판 완주"(mvp-scope 8장)가 구조적으로 불가능했다
- 새 판을 시작할 때 감염·유령·해독제 소지·배합 코드·미션 목록을 초기화한다.
  플레이어 NetworkObject가 씬 전환에도 살아남아 지난 판 상태가 넘어오기 때문이다
- 결과 화면에 전원 역할, 생존 여부, 개인 미션 수, 강화 3축 최종 단계,
  발견·놓친 단서 수를 공개한다(GDD 20). 라운드 중에는 목록이 비어 있다
- 사건 타임라인은 컷라인(로드맵 14장 3번, mvp-scope 9장 7번)에 따라 제외했다
- 연결이 끊기면 30초를 기다린다. 유예 중인 생존자는 현실 생존자 수에 계속 센다
- 빌런이 돌아오지 않으면 생존자 승리로 확정한다(GDD 19.2). 판정 입력과 우선순위는
  빌런 퇴출과 같고 결과 화면 문구만 "접속을 종료해 돌아오지 않았습니다"로 구분한다
- 호스트가 종료되면 경기를 무효 처리하고 로비 씬으로 돌아간다(GDD 19.1).
  NGO가 멈춘 뒤에도 동작해야 하므로 감시자는 NetworkBehaviour가 아닌 일반 컴포넌트다
- Unity 인증 PlayerId로 새 clientId를 기존 참가자 신원에 연결하고 30초 안에 돌아오면
  같은 슬롯·역할·위치·미션·감염·해독제 소지를 복원한다. 배합 코드는 저장하지 않는
  개인 기억 정보라 재접속 시 복원하지 않는다
- 미복귀 생존자의 미완료 미션은 같은 스테이션의 공용 복구 목록으로 옮긴다(GDD 19.2).
  다른 살아 있는 생존자가 완료하면 원래 이탈자의 남은 점수 예산으로 반영해 100%를 보존한다
- 유령의 개인 미션은 계속 허용하되 공용 복구 목록은 공용 패널 규칙에 따라 조작하지 못한다

### 이름표와 미션 목록

- 라운드 화면에서 각 플레이어 위에 `슬롯번호. 닉네임`을 표시한다(mvp-scope 3.3)
- 색상만으로 구분하지 않고 번호를 함께 붙인다(GDD 21)
- 유령 이름표는 살아 있는 플레이어에게 보이지 않는다(GDD 17)

- `Tab`으로 전체 미션 목록과 전자지도를 여닫는다(GDD 7.2). 입력 액션에 `Journal`을 추가했다

  75% 이후 남은 미션 구역 안내에도 함께 포함한다

## 직접 실행 방법

1. 2D 생성 파일이 없거나 맵을 재생성할 때만 `Tools > Monkey Lab > Build Complete 2D Top Down`을 실행한다.
2. 온라인 흐름은 Unity에서 `Assets/_Project/Scenes/00_Bootstrap.unity`를 열고 재생한다.
3. 메인 메뉴에서 `방 만들기` 또는 참가 코드 입력 후 `코드로 참가`를 누른다.
4. 호스트는 6명 준비 후 `게임 시작`, 개발 검증은 `개발용 현재 인원 시작`을 누른다.
5. 연구소에서 각자 다른 슬롯·색상으로 생성되고 자기 캐릭터만 이동하는지 확인한다.
6. 2인 검증은 `Tools > Monkey Lab > Configure Host Client Play Mode`를 한 번 실행하고,
   상단 시나리오가 `HostClient2`인지 확인한 뒤 상단 재생 버튼을 누른다.
7. 로컬 게임플레이는 `Assets/_Project/Scenes/10_Laboratory.unity`를 열고 재생한다.
8. 화면 상단의 시작 보호 30초 동안 괴물이 순찰만 하는지 확인한다.
9. 보호 종료 후 원숭이의 짧은 원형 근접 범위에 들어가 밝은 빨간색 추격 상태를 확인한다.
10. 원숭이가 가까워지면 흰색 물기 상태와 피격 배너가 표시되고, 물기 성공 뒤 강제 소음
    시간이 남으면 현장 배회, 아니면 순찰로 복귀하는지 확인한다.
11. 물리면 우측 하단에 감염 타이머와 해독제 보유 상태가 표시된다.
12. 전력 복구실의 주황색 퓨즈 스테이션 가까이에서 `E`를 누른다.
13. 일부러 틀린 퓨즈를 눌러 소음 배너와 원숭이의 노란색 조사 상태를 확인한다. 현장 도착 시
   소음 위치 반경 5.33m 안에 있으면 밝은 빨간색 급습 추격으로 바뀌고 10초간 주변을 배회한다.
14. 원숭이는 소음 지점에서 보라색 탐색 상태를 거친 뒤 다시 순찰한다.
15. 해독 흐름은 새 재생에서 `Tools > Monkey Lab > Test Infection And Antidote`로 확인한다.
16. `Esc`로 미션을 취소하거나 `F`로 손전등을 켜고 끈다.
17. 강화는 빌런으로 배정된 인스턴스에서 실험실 B·보안실·백신실 B의 일반 미션 패널에
   `E`로 접근해 밸브 드래그·회로 클릭·타이밍 주입을 수행한다. 같은 패널의 시민에게는 시민
   퍼즐이 열리고, `Esc`나 이탈로 각자 진행만 즉시 초기화되는지도 함께 본다.
18. 개체 강화 성공 시 격리실 A에서 3초 경고 후 두 마리가 추가되는지 확인한다.
19. 강화 성공 시 해당 현장(실험실 B·격리실 A·백신실 B) 7m 안에 시민이 있으면 단서가
   나타나지 않아야 한다. 시민이 모두 떠난 뒤 양쪽 화면에 익명 단서가 나타나고 라운드가
   끝날 때까지 사라지지 않는지 확인한다.
20. 빌런 화면 우측의 `스피커 지도 열기`로 방을 고르면 그 방 스피커가 3초간 노란색으로 켜지고,
   반경 40m 안의 괴물이 모두 조사 상태로 전환되는지 확인한다.
21. 스피커 사용 후 그 방 스피커 옆에 붉은 LED가 남고, 45초 쿨타임이 빌런 화면에만
   표시되는지 확인한다.
22. 탐색 120초 이후 좌측 하단 `회의 호출`을 누르면 토론 90초 → 투표 30초 → 결과 5초를
   거쳐 탐색으로 돌아오는지 확인한다.

    결계(`x -42.5~38`, `y -25~32`)에서 더 나가지 못하는지 확인한다.
27. 살아 있는 인스턴스에서 유령이 보이지 않고, 유령끼리는 반투명으로 보이는지 확인한다.

   스피커를 켠 시각과 방이 기록되는지 확인한다.

   표시되고 다른 인스턴스에는 보이지 않는지 확인한다.

   5자리를 입력하면 합성 4초 뒤 초록색 `Ready`가 되는지 확인한다.
   자리를 떠나도 합성이 계속 진행되는지 확인한다.

   입력만 초기화되는지 확인한다. 오입 시 소음이 발생하지 않는지도 확인한다.
32. 감염 중에는 이동 속도가 눈에 띄게 느려지고, 치료 후 즉시 정상 속도로 돌아오는지
   확인한다.

   집을 수 없는지 확인한다.
35. 빌런 역할로도 PC에서 코드를 발급받고 제작대에서 배합해 완성품을 얻을 수 있는지
   확인한다.

37. `<color=red>글자</color>`를 보내면 태그가 지워지고 `글자`만 남는지 확인한다.
38. 1초 안에 두 번 보내면 두 번째가 무시되는지 확인한다.

40. 회의를 두 번 열었을 때 두 번째 회의에서 이전 발언이 남지 않는지 확인한다.

   남은 값에서 이어지는지 빌런 화면에서 확인한다.
42. 회의가 끝난 직후 옆에 괴물이 있어도 2초 동안 물리지 않는지 확인한다.
43. 라운드가 끝나면 결과 화면에 전원 역할·생존 여부·미션 수·강화 단계·단서 수가
   나오는지 확인한다.
44. 호스트 화면의 `로비로 돌아가기`로 메인 메뉴에 돌아가 다시 시작했을 때,
   지난 판에서 유령이었던 사람이 살아서 시작하는지 확인한다.
45. 참가자 인스턴스를 강제 종료하고 30초 뒤 판정이 바뀌는지 확인한다.
   빌런이 나가면 생존자 승리로 끝나야 한다.

   보이지 않는지 확인한다.

### 오디오 (M6 "정보성 효과음") — 통째로 미구현

2026-08-05 확인 결과, 소리 관련 자산과 배선이 전부 비어 있다.

| 항목 | 현재 상태 |
| --- | --- |
| 사운드 파일 | 프로젝트 전체에 0개 (`.wav`/`.ogg`/`.mp3` 없음) |
| AudioMixer 에셋 | 없음. 아트 가이드 §11의 7채널 구조가 문서에만 존재 |
| `SO_PresentationAssetCatalog_Default` 오디오 슬롯 | 6칸 모두 비어 있음 |
| 볼륨 설정 | 믹서가 없어 `RuntimeSettingsOverlay`가 씬의 `AudioSource`를 직접 찾아 `volume`을 곱하는 임시 방식 |

이 때문에 **M6 완료 조건 중 "화면을 보지 않아도 괴물 접근을 어느 정도 판단할 수 있다"가
현재 구조적으로 달성 불가능하다.** 월드의 대부분이 어두운 설계라 소리가 정보의 상당 부분을
담당해야 하는데(아트 가이드 §10), 괴물 소리가 아예 없다.

착수할 때 할 일:

1. 아트 가이드 §11 구조대로 AudioMixer 에셋을 만들고 `RuntimeSettingsOverlay`의
   `AudioSource` 직접 스캔 방식을 믹서 채널 노출로 교체한다.
2. 아트 가이드 §12 필수 사운드 목록을 채운다. 사운드 파일을 구하지 않고
   절차적 파형 생성으로 만드는 선택지도 있다(스프라이트를 절차 생성한 것과 같은 방식).
3. 카탈로그의 6개 오디오 슬롯을 연결한다.

### 프롭 최종 아트 교체 리졸버 — 미구현

`EnvironmentPropSlot`이 `AssetKey`·`Footprint`·`MountKind`·`ReplacementAnchor`·
`SetPlaceholderVisible()`를 모두 갖고 있지만 **이 슬롯을 읽어 실제로 교체해주는 코드가 없다.**
그림을 넣기 시작하는 시점에 `AssetKey → 스프라이트` 카탈로그 ScriptableObject와
이를 순회하는 리졸버가 필요하다 (아트 가이드 §4.1.2).

`RoundWinConditionService`는 SDD 16.1의 우선순위(빌런 퇴출 → 진행률 100% →
현실 생존자 0명 → 시간 만료)를 그대로 구현하고, 투표 결과의 `isVillainExiled`도
`NetworkRoundState`에 연결되어 있다.

M1 완료 조건인 이동, 미션 실패, 소음 조사, 괴물 추격·물기와 로컬 감염 흐름은 연결됐다.
M2의 인증, Relay Host+Client 2개 인스턴스 참가와 로비 공개 상태 동기화를 실제 Cloud에서
검증했다. M3의 서버 라운드·진행도·괴물·감염 동기화, 9종 회색상자와 결과 화면까지
구현했다. M4의 9개 작업(강화 3축, 4→6→8마리, 단서 4종, 스피커, 빌런 가짜 미션, 회의·투표,
퇴출·유령, CCTV·서버 로그, 동시 승패 우선순위)을 모두 구현했다.

유령 채팅과 CCTV 카메라 전환은 더 이상 미구현 항목이 아니다.
