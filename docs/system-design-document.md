# 시스템 설계서

> 문서 버전: 1.1
> 기준 GDD: 1.1
> 목적: 게임 규칙을 서버에서 일관되게 구현하기 위한 상태, 입력, 판정과 예외 정의

---

## 1. 설계 원칙

- 호스트가 게임 규칙의 유일한 판정자다.
- 클라이언트는 행동 의도를 보내고 결과를 표시한다.
- 하나의 사건은 서버에서 한 번만 확정한다.
- 역할과 개인 정보는 필요한 소유자에게만 전송한다.
- 모든 시간 기반 시스템은 공통 서버 시계를 사용한다.
- 회의 중 정지되는 시간과 계속되는 시간을 명시적으로 구분한다.
- 밸런스 값은 코드 상수 대신 데이터 에셋에서 읽는다.
- 승패가 확정된 뒤에는 추가 진행률, 감염, 투표 사건을 받지 않는다.

---

## 2. 시스템 불변 조건

다음 조건은 항상 참이어야 한다.

1. 한 세션에는 빌런이 정확히 한 명이다.
2. 한 미션은 한 번만 완료된다.
3. 빌런 미션은 프로젝트 진행률을 올리지 않는다.
4. 프로젝트 진행률은 0~100% 범위를 벗어나지 않는다.
5. 한 플레이어가 소지한 해독제는 최대 한 개다.
6. 각 제작기는 동시에 한 개만 생산한다.
7. 괴물 수는 현재 개체 강화 단계와 일치한다.
8. 한 플레이어는 동시에 하나의 플레이 상태만 가진다.
9. 유령은 공유 월드 오브젝트를 조작하지 못한다.
10. 회의 중에는 월드 시뮬레이션이 정지한다.
11. 라운드 결과는 한 번만 확정된다.

## 3. 전체 게임 상태

```text
Boot
  → MainMenu
  → Lobby
  → Loading
  → RoleReveal
  → GracePeriod
  → Exploration
      ↔ MeetingDiscussion
      → MeetingVote
      → MeetingResolution
      → Exploration
  → RoundResult
  → Lobby
```

| 상태 | 허용 입력 | 서버 동작 | 종료 조건 |
| --- | --- | --- | --- |
| Lobby | 준비, 색상, 시작 | 참가자 관리 | 호스트 시작 |
| Loading | 없음 | 씬 로드 확인 | 전원 로드 완료 또는 시간 초과 |
| RoleReveal | 확인 | 역할·미션 개인 전송 | 5초 경과 |
| GracePeriod | 이동, 손전등, 미션 확인 | 30초 타이머, 괴물 순찰 | 30초 경과 |
| Exploration | 모든 게임 입력 | 전체 월드 시뮬레이션 | 회의 또는 승패 |
| MeetingDiscussion | 채팅 | 월드 정지, 90초 타이머 | 90초 또는 전원 준비 |
| MeetingVote | 투표 | 월드 정지, 30초 타이머 | 전원 투표 또는 30초 |
| MeetingResolution | 없음 | 결과·퇴출·승패 판정 | 5초 경과 |
| RoundResult | 다시 하기, 나가기 | 통계 공개 | 로비 복귀 |

### 3.1 로드 시간 초과

- 한 명이라도 30초 안에 게임 씬 로드를 완료하지 못하면 15초 추가 유예를 알린다.
- 추가 유예 이후에도 실패하면 해당 플레이어를 세션에서 제거하고 로비로 복귀한다.
- MVP는 6명 미만 정상 매치를 시작하지 않는다.

## 5. 플레이어 상태

### 5.1 생명 상태

```text
AliveHealthy
  → AliveInfected
  → AliveHealthy  (해독제 사용)
  → DeadGhost     (타이머 0)

AliveHealthy / AliveInfected
  → ExiledGhost   (생존자 퇴출)
```

빌런은 `AliveHealthy`만 사용하며 물기 연출용 임시 상태를 별도로 둔다.

### 5.2 행동 상태

- Free
- Interacting
- DoingMission
- CarryingBattery
- UsingAntidote
- InMeeting
- GhostMoving
- DisconnectedGrace

행동 상태는 생명 상태와 조합되지만 상호 배타적인 입력 잠금을 갖는다. 예를 들어 `DoingMission` 중에는 이동할 수 없고, `CarryingBattery` 중에는 이동 속도만 감소한다.

### 5.3 역할별 공개 정보

| 정보 | 본인 | 같은 생존자 | 빌런 | 결과 이후 |
| --- | --- | --- | --- | --- |
| 역할 | 공개 | 비공개 | 자기 역할만 공개 | 전원 공개 |
| 개인 미션 | 공개 | 비공개 | 가짜 목록만 공개 | 요약 공개 |
| 레시피 | 공개 | 비공개 | 빌런에게 없음 | 공개하지 않음 |
| 감염 타이머 | 공개 | 상태 아이콘만 | 타인과 동일 | 타임라인 공개 |
| 스피커 쿨타임 | 빌런만 | 비공개 | 공개 | 타임라인 공개 |
| 강화 진행 | 빌런만 | 비공개 | 공개 | 전원 공개 |

## 6. 상호작용 시스템

### 6.1 상호작용 요청

클라이언트가 다음 데이터를 서버에 보낸다.

```text
playerId
targetNetworkId
interactionType
clientSequence
```

서버는 다음을 검증한다.

- 플레이어가 살아 있거나 해당 유령 미션을 수행할 수 있는가?
- 대상과의 경로상 거리가 상호작용 범위 이내인가?
- 대상이 활성 상태인가?
- 다른 플레이어가 점유하지 않았는가?
- 현재 게임 상태에서 허용되는가?
- 역할과 소유권이 맞는가?

### 6.2 공통 범위

- 일반 오브젝트: 약 1.5m
- 아이템 획득: 약 1.2m
- 문: 약 1.8m
- 유령 개인 미션: 약 1.5m, 벽 통과 위치 악용 방지를 위해 대상 앞 접근점 사용

### 6.3 점유

- 미션, 제작기 조작, CCTV, 서버 로그는 한 번에 한 명만 사용한다.
- 사용자가 이동, 회의, 사망, 연결 종료하면 점유를 해제한다.
- 10초 동안 유효 입력이 없으면 점유를 자동 해제한다.

## 7. 역할 및 미션 배정

### 7.1 역할 배정

1. 참가자 목록을 서버 난수로 섞는다.
2. 한 명을 빌런으로 지정한다.
3. 최근 역할 기록은 MVP에서 반영하지 않는다.
4. 역할은 소유 클라이언트에만 개인 메시지로 전송한다.

### 7.2 생존자 미션 배정

- 각 생존자에게 어려운 미션이 포함되면 4개, 쉬운 미션 중심이면 5개를 준다.
- 같은 플레이어에게 같은 스테이션을 중복 배정하지 않는다.
- 첫 미션이 모두 한 구역에 몰리지 않도록 시작 위치와 거리를 검사한다.
- 다섯 생존자의 총기여도는 각 20%다.
- 한 라운드에서 최소 세 종류 이상의 미니게임을 사용한다.

### 7.3 진행률 계산

```text
playerContribution = 20 / assignedMissionCount
projectProgress = 모든 완료 미션의 playerContribution 합
```

부동소수 누적 오류를 피하기 위해 내부에서는 10,000 포인트를 100%로 사용한다. 각 플레이어에게 2,000 포인트를 배정하고 마지막 미션이 나머지 오차를 가진다.

## 8. 미션 상태

```text
Assigned
  → InProgress
  → Failed → Assigned
  → Cancelled → Assigned
  → Completed
```

### 8.1 시작

- 소유자와 스테이션을 검증한다.
- 스테이션을 점유한다.
- 서버가 미션 인스턴스 시드와 제한값을 보낸다.

### 8.2 입력

- 클라이언트는 조작 결과가 아니라 버튼·슬롯·타이밍 입력을 보낸다.
- 서버는 입력 순서와 허용 시간을 검증한다.
- 연속 입력에는 증가하는 `clientSequence`를 사용한다.

### 8.3 성공

- 서버가 `Completed`로 원자적 변경한다.
- 프로젝트 포인트를 한 번만 더한다.
- 성공 VFX와 소리를 전송한다.
- 개인 목록과 공용 게이지를 갱신한다.

### 8.4 실패

- 실패 유형에 따라 소음 강도를 결정한다.
- 스테이션 점유를 해제한다.
- 짧은 재시도 지연 후 `Assigned`로 돌아간다.

## 9. 소음 이벤트

### 9.1 데이터

```text
noiseId
sourceType
worldPosition
roomId
pathRadius
intensity
createdServerTime
duration
```

### 9.2 우선순위 점수

괴물마다 유효 후보에 대해 다음 순서로 비교한다.

1. 2D 웨이포인트 그래프 경로 거리가 반경 이내인지 확인
2. 경로 거리가 더 짧은 후보
3. 강도가 더 큰 후보
4. 발생 시각이 더 최근인 후보
5. 마지막으로 `noiseId`가 작은 후보

마지막 조건은 모든 클라이언트와 재생 로그에서 결과를 재현하기 위한 결정 규칙이다.

### 9.3 갱신

- 소리 조사 중 더 가까운 강한 소음이 발생하면 목표를 바꿀 수 있다.
- 이미 근접 감지나 소음 현장 급습으로 플레이어를 추격 중이면 일반 미션 소음은 무시한다.
- 스피커 소음은 추격 중인 괴물을 강제로 돌리지 않는다.
- 표적을 잃은 수색 상태에서는 새 소음에 반응한다.

## 10. 괴물 AI

### 10.1 상태 머신

| 상태 | 진입 | 행동 | 종료 |
| --- | --- | --- | --- |
| Patrol | 기본 | 순찰 지점 이동 | 방 도착, 소음, 감지 |
| RoomIdle | 방 도착 | 약 6초 대기하며 원형 근접 감지 | 시간 경과, 소음, 감지 |
| InvestigateNoise | 유효 소음 | 6초 가속으로 위치 이동 | 도착, 근접 감지, 경로 실패 |
| Chase | 원형 근접 감지·소음 현장 급습 | 대상까지 2D 경로 추적 | 물기 범위, 표적 상실 |
| Bite | 범위 진입 | 논리 방향 고정 후 물기 판정 | 실패·회피 시 재추격, 성공 시 순찰 |
| Search | 표적 상실·소리 도착·물기 성공 | 근처 수색 지점 이동 | 3초 경과 또는 감지 |
| RecoverPath | 경로 실패 | 가까운 유효 2D 웨이포인트 탐색 | 복구 또는 강제 순찰 배치 |

### 10.2 감지

- 원숭이는 시야 감지를 사용하지 않는다.
- 평상시에는 방향과 무관한 강화 단계별 원형 근접 감지 반경만 사용한다.
- 원형 근접 감지는 2D 경로 그래프로 접근 가능한 대상만 허용한다.
- 소리 조사 중에는 이동 경로에서 평상시 근접 범위에 닿은 대상만 즉시 추격한다.
- 소음 위치에 도착하면 해당 위치 반경 8m 안의 접근 가능한 대상을 선택해 조사 속도를 유지한 채 급습한다.
- `AliveInfected` 생존자는 감염된 동료로 취급해 근접 감지·급습·추격·물기 후보에서 제외한다.
- 유령은 감지 대상이 아니다.
- 빌런은 감지·추격 대상이지만 감염 대상이 아니다.

### 10.3 물기

1. 서버가 물기 거리와 벽 등 물리 장애물을 다시 검사한다.
2. 대상이 건강한 생존자 또는 물기 연출 대상 빌런인지 확인하고, 감염자·유령은 거부한다.
3. 대상이 물기 보호 상태인지 확인한다.
4. 물기 애니메이션 시작 사건을 보낸다.
5. 판정 프레임에 대상이 여전히 범위 안이면 감염을 적용한다.
6. 대상에게 1.5초 물기 보호를 준다.

물기 성공 후에는 해당 표적을 감염된 동료로 처리하고 회복 동작이 끝나면 즉시 순찰로 복귀한다.
물기가 빗나가거나 보호 상태로 막힌 경우에는 정상 추격 판단으로 복귀한다.

빌런에게는 3~4번의 시각 사건만 보내고 감염을 생성하지 않는다.

### 10.4 끼임 복구

- 2초 동안 목적지 방향 이동량이 기준 이하이면 경로를 재계산한다.
- 세 번 연속 실패하면 가까운 순찰 지점으로 이동 목표를 바꾼다.
- 이동 가능 영역을 이탈한 경우 가장 가까운 2D 웨이포인트로 서버가 재배치한다.
- 문 하나에 괴물이 과도하게 겹치지 않도록 로컬 회피 우선순위를 다르게 설정한다.

## 11. 강화 시스템

### 11.1 데이터

각 강화 축은 `0, 1, 2` 단계 정수로 저장한다.

- `ScentLevel`
- `PopulationLevel`
- `ToxicityLevel`

### 11.2 완료 처리

1. 빌런 소유와 대상 스테이션을 검증한다.
2. 해당 축이 2단계 미만인지 확인한다.
3. 단계를 한 번 증가시킨다.
4. 효과를 적용한다.
5. 현장 단서를 생성한다.
6. 중요 사건 로그를 남긴다.
7. 빌런 UI를 갱신한다.

### 11.3 개체 강화

- 1단계: 격리실 A에서 두 마리 생성
- 2단계: 격리실 B에서 두 마리 생성
- 3초간 문 경고등과 경보를 재생한 뒤 활성화한다.
- 회의 호출이 경고 중 발생하면 남은 경고 시간을 보존한다.

### 11.4 독성 강화

이미 감염된 생존자의 제한시간은 변경하지 않는다. 강화 이후 새로 물린 생존자에게만 새 단계 값을 적용한다.

## 12. 해독제 시스템

### 12.1 제작기 상태

```text
Idle
  → Producing
  → Ready
  → Idle (누군가 획득)
```

| 상태 | 조작 |
| --- | --- |
| Idle | 레시피 보유 생존자가 제작 시작 |
| Producing | 남은 시간 확인만 가능 |
| Ready | 누구나 획득 가능 |

### 12.2 제작 시작 검증

- 생존자 역할인가?
- 살아 있는가?
- 개인 레시피를 발견했는가?
- 제작기가 `Idle`인가?
- 상호작용 범위 안인가?

빌런은 제작을 시작할 수 없지만 완성품 획득과 보관은 가능하다.

### 12.3 획득·보관

- 소지 슬롯이 비어 있어야 획득한다.
- 완성품 획득은 선착순 서버 판정이다.
- 지정 보관 칸은 여러 슬롯을 가질 수 있다.
- 보관 칸 상태는 접근한 플레이어에게 공개한다.
- 아이템 소유권 변경은 사건 로그에 기록하지만 라운드 중 사용자에게 공개하지 않는다.

## 13. 감염 시스템

### 13.1 감염 인스턴스

```text

```

### 13.2 재물림

- `AliveInfected` 상태가 되면 `MonsterTarget`을 감지 불가로 전환한다.
- 괴물은 해당 생존자를 추격·물기하지 않고 물기 회복 뒤 순찰로 복귀한다.
- 치료가 완료되면 `MonsterTarget`을 다시 감지 가능으로 전환해 새 감염을 받을 수 있다.

### 13.3 사망

타이머가 0에 도달하면 서버가 한 번만 다음을 수행한다.

1. 진행 중 행동 취소
2. 소지 해독제를 지정 드롭 지점에 놓음
3. `DeadGhost` 전환
4. 캐릭터 충돌과 생존자 시각 모델 비활성화
5. 유령 모델을 소유 클라이언트와 다른 유령에게만 활성화
6. 현실 생존자 수와 승패 확인

## 14. 단서와 정보 시스템

### 14.1 단서 상태

- `Inactive`: 생성 전
- `ActiveUninspected`: 월드에 존재
- `ActiveInspected`: 한 명 이상 조사

조사 여부는 업적이나 결과 통계용이며 단서는 조사하지 않아도 보인다.

### 14.2 영구 단서

- 강화마다 연결된 단서 오브젝트를 활성화한다.
- 같은 축의 2회 강화는 단서 강도를 높이거나 두 번째 위치에 추가 흔적을 만든다.
- 단서는 라운드 종료까지 비활성화하지 않는다.

### 14.3 CCTV와 로그

- 프로젝트 50% 미만에는 단말기가 잠겨 있다.
- 50% 도달 사건으로 서버가 활성화한다.
- CCTV는 클라이언트 로컬 카메라를 전환하지만 관찰 가능한 플레이어 위치는 서버 동기 상태를 사용한다.
- 로그 조회 범위와 보존 시간은 밸런스 데이터에서 설정한다.

## 15. 회의 시스템

### 15.1 호출 검증

- 현재 상태가 `Exploration`인가?
- 호출자가 살아 있는가?
- 시작 후 탐색 시간 2분이 지났는가?
- 공용 쿨타임이 0인가?
- 사용 회의 수가 3회 미만인가?
- 이미 승패가 확정되지 않았는가?

여러 호출이 동시에 도착하면 서버가 먼저 받은 유효 요청 하나만 승인한다.

### 15.2 회의 진입

1. 게임 상태를 `MeetingDiscussion`으로 전환한다.
2. 진행 중 미션과 사용 행동을 취소한다.
3. 모든 월드 시계를 정지한다.
4. 살아 있는 참가자 목록과 토론 종료 시각을 전송한다.
5. 채팅 채널을 회의 참가자로 제한한다.

### 15.3 투표 집계

- 각 플레이어의 마지막 유효 표 한 개만 저장한다.
- 시간 안에는 표를 변경할 수 있다.
- 투표 종료 시 미투표자는 기권으로 바꾼다.
- 기권을 포함한 최고 득표가 둘 이상이면 퇴출하지 않는다.
- 기권이 단독 최고여도 퇴출하지 않는다.
- 플레이어 한 명이 단독 최고일 때만 퇴출한다.

### 15.4 회의 종료 보호

월드 재개 후 모든 살아 있는 플레이어에게 2초간 물기 보호를 준다. 괴물은 기존 위치에서 다시 판단하며 회의 직전 목표를 강제로 유지하지 않는다.

## 16. 승패 판정

승패 검사는 다음 사건 이후 실행한다.

- 미션 완료
- 투표 해결
- 생존자 사망
- 연결 종료 유예 만료
- 탐색 타이머 틱

### 16.1 우선순위

```text
1. 빌런 퇴출       → SurvivorWin
2. 진행률 100%     → SurvivorWin
3. 현실 생존자 0명 → VillainWin
4. 탐색 시간 0     → VillainWin
```

판정 함수는 이미 결과가 있으면 즉시 반환한다. 결과를 확정한 서버 틱 이후에는 월드 입력을 거부한다.

## 17. 연결 종료

### 17.1 호스트

- 세션 연결 종료를 전원에게 알린다.
- 현재 경기를 무효로 표시한다.
- 메인 메뉴 또는 재접속 안내 화면으로 이동한다.

### 17.2 생존자 클라이언트

- 30초간 `DisconnectedGrace` 상태
- 캐릭터는 이동·충돌·감지 대상에서 제외
- 재접속 시 기존 상태와 소유권 복원
- 만료 시 `DeadGhost`로 처리
- 미완료 미션은 동일 스테이션의 공용 복구 미션으로 전환

### 17.3 빌런 클라이언트

- 30초 유예 후 미복귀 시 생존자 승리
- 유예 중에는 빌런 능력을 사용할 수 없다.
