# 시스템 설계서

> 문서 버전: 1.8
> 기준 GDD: 1.9
> 목적: 게임 규칙을 서버에서 일관되게 구현하기 위한 상태, 입력, 판정과 예외 정의

---

## 1. 설계 원칙

- 호스트가 게임 규칙의 유일한 판정자다.
- 클라이언트는 행동 의도를 보내고 결과를 표시한다.
- 하나의 사건은 서버에서 한 번만 확정한다.
- 역할과 개인 정보는 필요한 소유자에게만 전송한다.
- 모든 시간 기반 시스템은 공통 서버 시계를 사용한다.
- 회의 중 정지되는 시간과 계속되는 시간을 명시적으로 구분한다.
- 밸런스 값은 코드 상수 대신 데이터 에셋에서 읽는다.
- 승패가 확정된 뒤에는 추가 진행률, 감염, 투표 사건을 받지 않는다.

---

## 2. 시스템 불변 조건

다음 조건은 항상 참이어야 한다.

1. 한 세션에는 빌런이 정확히 한 명이다.
2. 한 미션은 한 번만 완료된다.
3. 빌런 미션은 프로젝트 진행률을 올리지 않는다.
4. 프로젝트 진행률은 0~100% 범위를 벗어나지 않는다.
5. 한 플레이어가 소지한 해독제는 최대 한 개다.
6. 각 제작기는 동시에 한 개만 생산한다.
7. 괴물 수는 현재 개체 강화 단계와 일치한다.
8. 한 플레이어는 동시에 하나의 플레이 상태만 가진다.
9. 유령은 공유 월드 오브젝트를 조작하지 못한다.
10. 회의 중에는 월드 시뮬레이션이 정지한다.
11. 라운드 결과는 한 번만 확정된다.

## 3. 전체 게임 상태

```text
Boot
  → MainMenu
  → Lobby
  → Loading
  → RoleReveal
  → GracePeriod
  → Exploration
      ↔ MeetingDiscussion
      → MeetingVote
      → MeetingResolution
      → Exploration
  → RoundResult
  → Lobby
```

| 상태 | 허용 입력 | 서버 동작 | 종료 조건 |
| --- | --- | --- | --- |
| Lobby | 준비, 색상, 시작 | 참가자 관리 | 호스트 시작 |
| Loading | 없음 | 씬 로드 확인 | 전원 로드 완료 또는 시간 초과 |
| RoleReveal | 확인 | 역할·미션 개인 전송 | 7초 경과 |
| GracePeriod | 이동, 손전등, 미션 수행 | 30초 타이머, 라운드 시계 시작, 괴물 순찰(추격·물기 없음) | 30초 경과 |
| Exploration | 모든 게임 입력 | 전체 월드 시뮬레이션 | 회의 또는 승패 |
| MeetingDiscussion | 채팅 | 월드 정지, 90초 타이머 | 90초 또는 전원 준비 |
| MeetingVote | 투표 | 월드 정지, 30초 타이머 | 전원 투표 또는 30초 |
| MeetingResolution | 없음 | 결과·퇴출·승패 판정 | 5초 경과 |
| RoundResult | 다시 하기, 나가기 | 통계 공개 | 로비 복귀 |

### 3.1 로드 시간 초과

- 한 명이라도 30초 안에 게임 씬 로드를 완료하지 못하면 15초 추가 유예를 알린다.
- 추가 유예 이후에도 실패하면 해당 플레이어를 세션에서 제거하고 로비로 복귀한다.
- MVP는 6명 미만 정상 매치를 시작하지 않는다.

## 5. 플레이어 상태

### 5.1 생명 상태

```text
AliveHealthy
  → AliveInfected
  → AliveHealthy  (해독제 사용)
  → DeadGhost     (타이머 0)

AliveHealthy / AliveInfected
  → ExiledGhost   (생존자 퇴출)
```

빌런은 `AliveHealthy`만 사용하며 물기 판정과 감염 상태로 전이하지 않는다.

### 5.2 행동 상태

- Free
- Interacting
- DoingMission
- CarryingBattery
- UsingAntidote
- InMeeting
- GhostMoving
- DisconnectedGrace

행동 상태는 생명 상태와 조합되지만 상호 배타적인 입력 잠금을 갖는다. 예를 들어 `DoingMission` 중에는 이동할 수 없고, `CarryingBattery` 중에는 이동 속도만 감소한다.

### 5.3 역할별 공개 정보

| 정보 | 본인 | 같은 생존자 | 빌런 | 결과 이후 |
| --- | --- | --- | --- | --- |
| 역할 | 공개 | 비공개 | 자기 역할만 공개 | 전원 공개 |
| 개인 미션 | 공개 | 비공개 | 가짜 목록만 공개 | 요약 공개 |
| 배합 코드 | 공개 | 비공개 | 본인 것만 공개 | 공개하지 않음 |
| 감염 타이머 | 공개 | 상태 아이콘만 | 타인과 동일 | 타임라인 공개 |
| 스피커 쿨타임 | 빌런만 | 비공개 | 공개 | 타임라인 공개 |
| 강화 진행 | 빌런만 | 비공개 | 공개 | 전원 공개 |

## 6. 상호작용 시스템

### 6.1 상호작용 요청

클라이언트가 다음 데이터를 서버에 보낸다.

```text
playerId
targetNetworkId
interactionType
clientSequence
```

서버는 다음을 검증한다.

- 플레이어가 살아 있거나 해당 유령 미션을 수행할 수 있는가?
- 대상과의 경로상 거리가 상호작용 범위 이내인가?
- 대상이 활성 상태인가?
- 다른 플레이어가 점유하지 않았는가?
- 현재 게임 상태에서 허용되는가?
- 역할과 소유권이 맞는가?

### 6.2 공통 범위

- 일반 오브젝트: 약 1.5m
- 아이템 획득: 약 1.2m
- 문: 약 1.8m
- 유령 개인 미션: 약 1.5m, 벽 통과 위치 악용 방지를 위해 대상 앞 접근점 사용

### 6.3 점유

- 미션, 제작기 조작, CCTV, 서버 로그는 한 번에 한 명만 사용한다.
- 사용자가 이동, 회의, 사망, 연결 종료하면 점유를 해제한다.
- 10초 동안 유효 입력이 없으면 점유를 자동 해제한다.

## 7. 역할 및 미션 배정

### 7.1 역할 배정

1. 참가자 목록을 서버 난수로 섞는다.
2. 한 명을 빌런으로 지정한다.
3. 최근 역할 기록은 MVP에서 반영하지 않는다.
4. 역할은 소유 클라이언트에만 개인 메시지로 전송한다.

### 7.2 생존자 미션 배정

미션 풀은 방 10개에 걸쳐 생존자용 22개다(GDD §10.2). 해독제 배합(백신실 A/B, GDD §14)은
이 풀과 별도이며 진행률에 반영되지 않는다.

- 각 생존자에게 어려운 미션이 포함되면 4개, 쉬운 미션 중심이면 5개를 준다.
- 같은 플레이어에게 같은 스테이션을 중복 배정하지 않는다.
- 같은 라운드에서 하나의 스테이션은 한 생존자에게만 배정한다. 서버 권위 퍼즐 상태와
  완료 점수가 서로 다른 플레이어 사이에서 공유되는 문제를 막기 위한 제약이다.
- 첫 미션이 모두 한 구역에 몰리지 않도록 시작 위치와 거리를 검사한다.
- 다섯 생존자의 총기여도는 각 20%다.
- 한 라운드에서 최소 세 종류 이상의 미니게임을 사용한다.
- 공통 조작은 `E`로 스테이션 열기 → 마우스로 미니게임 조작 → `ESC`로 닫기다.

### 7.2.1 빌런 미션 배정

- 빌런 전용 미션 6종(GDD §13.2) 중 서버가 4개를 무작위로 배정한다.
- 배정된 4개는 각각 방이 다른 위장 오브젝트에서 진행되며, 같은 자리의 생존자 미션과
  겉모습을 공유한다.
- 빌런에게는 시민 개인 미션 목록 대신 배정된 4개만 표시한다.

### 7.3 진행률 계산

```text
playerContribution = 20 / assignedMissionCount
projectProgress = 모든 완료 미션의 playerContribution 합
```

부동소수 누적 오류를 피하기 위해 내부에서는 10,000 포인트를 100%로 사용한다. 각 플레이어에게 2,000 포인트를 배정하고 마지막 미션이 나머지 오차를 가진다.

## 8. 미션 상태

```text
Assigned
  → InProgress
  → Failed → Assigned
  → Cancelled → Assigned
  → Completed
```

### 8.1 시작

- 소유자와 스테이션을 검증한다.
- 스테이션을 점유한다.
- 서버가 미션 인스턴스 시드와 제한값을 보낸다.

### 8.2 입력

- 클라이언트는 조작 결과가 아니라 버튼·슬롯·타이밍 입력을 보낸다.
- 서버는 입력 순서와 허용 시간을 검증한다.
- 연속 입력에는 증가하는 `clientSequence`를 사용한다.

### 8.3 성공

- 서버가 `Completed`로 원자적 변경한다.
- 프로젝트 포인트를 한 번만 더한다.
- 성공 VFX와 소리를 전송한다.
- 개인 목록과 공용 게이지를 갱신한다.

### 8.4 실패

- 실패 유형에 따라 소음 강도를 결정한다.
- 스테이션 점유를 해제한다.
- 짧은 재시도 지연 후 `Assigned`로 돌아간다.

## 9. 소음 이벤트

### 9.1 데이터

```text
noiseId
sourceType
worldPosition
roomId
pathRadius
intensity
createdServerTime
duration
```

### 9.2 우선순위 점수

괴물마다 유효 후보에 대해 다음 순서로 비교한다.

1. 2D 웨이포인트 그래프 경로 거리가 반경 이내인지 확인
2. 경로 거리가 더 짧은 후보
3. 강도가 더 큰 후보
4. 발생 시각이 더 최근인 후보
5. 마지막으로 `noiseId`가 작은 후보

마지막 조건은 모든 클라이언트와 재생 로그에서 결과를 재현하기 위한 결정 규칙이다.

### 9.3 갱신

- 소리 조사 중 더 가까운 강한 소음이 발생하면 목표를 바꿀 수 있다.
- 미션 실패와 스피커는 강제 급습 소음이다. 경로 반경 안의 모든 괴물이 기존 근접 추격과
  물기 준비를 취소하고 소음 현장을 최우선 목표로 삼는다.
- 강제 급습 중에는 이동 경로에서 만난 다른 플레이어로 목표를 바꾸지 않는다. 현장에 도착한
  뒤 반경 8m 안의 접근 가능한 플레이어를 급습한다.
- 강제 급습이 아닌 일반 환경 소음은 이미 추격·물기 중인 괴물을 돌리지 않는다.
- 표적을 잃은 수색 상태에서는 새 소음에 반응한다.

## 10. 괴물 AI

### 10.1 상태 머신

| 상태 | 진입 | 행동 | 종료 |
| --- | --- | --- | --- |
| Patrol | 기본 | 순찰 지점 이동 | 방 도착, 소음, 근접 감지 |
| RoomIdle | 방 도착 | 약 6초 대기하며 근접 감지 | 시간 경과, 소음, 감지 |
| InvestigateNoise | 유효 소음 | 일반 소음은 최대 6초 가속, 미션 실패·스피커는 현장까지 급속 이동 | 도착, 근접 감지, 경로 실패 |
| Chase | 근접 감지·소음 현장 급습 | 대상까지 2D 경로 추적 | 물기 범위, 반경 이탈로 표적 상실 |
| Bite | 범위 진입 | 논리 방향 고정 후 물기 판정 | 실패·회피 시 재추격, 성공 시 강제 소음 배회 또는 순찰 |
| Search | 표적 상실·소리 도착·물기 성공 | 일반 수색 또는 강제 소음원 주변 난폭 배회 | 일반 5초·강제 소음 도착 후 10초 경과 또는 감지 |
| RecoverPath | 경로 실패 | 가까운 유효 2D 웨이포인트 탐색 | 복구 또는 강제 순찰 배치 |

### 10.2 감지

- 원숭이는 방향·시야각 감지를 사용하지 않는다.
- 평상시에는 빌런 미션 스택 단계(GDD §12.3, §13.3)별 콜라이더 표면 간 원형 근접 감지
  반경 안의 대상을 선택한다. 손전등 상태와 이동 여부는 감지에 관여하지 않는다.
- 근접 추적 또는 물기 준비 중 대상이 반경 밖으로 벗어나면 표적을 잃고 마지막 위치를 수색한다.
- 소음 조사와 현장 급습도 같은 기준을 쓴다. 미션 실패, 스피커, 경보와 배터리 낙하가
  괴물을 현장으로 끌어온다.
- 원형 근접 감지는 2D 경로 그래프로 접근 가능한 대상만 허용한다.
- 일반 소리 조사 중에는 이동 경로에서 평상시 근접 범위에 닿은 대상만 즉시 추격한다.
  미션 실패·스피커 강제 급습은 이 전환을 금지하고 현장 도착을 우선한다.
- 미션 실패 위치에 도착하면 반경 5.33m, 빌런 스피커 위치에 도착하면 반경 8m 안의
  접근 가능한 대상을 선택해 조사 속도를 유지한 채 급습한다.
- 강제 소음 현장 도착 후 10초간 해당 반경을 유지한다. 표적이 없거나 추격 중 놓치면
  소음원 주변의 접근 가능한 경로 지점을 빠르게 배회하고, 시간이 끝나면 평상 순찰로 복귀한다.
- 평상시 감지 반경은 기본 1.25m, 빌런 미션 스택 4단계에서 1.75m이며(GDD §13.3), 물기는
  원숭이와 플레이어의 콜라이더 표면 간격이 0.2m 이하여야 시작한다.
- `AliveInfected` 생존자는 감염된 동료로 취급해 근접 감지·급습·추격·물기 후보에서 제외한다.
- 유령은 감지 대상이 아니다.
- 빌런은 감지·추격 대상이지만 물기·감염 대상이 아니다.

### 10.3 물기

1. 서버가 물기 거리와 벽 등 물리 장애물을 다시 검사한다.
2. 대상이 건강한 생존자인지 확인하고, 빌런·감염자·유령은 거부한다.
3. 대상이 물기 보호 상태인지 확인한다.
4. 물기 애니메이션 시작 사건을 보낸다.
5. 판정 프레임에 대상이 여전히 범위 안이면 감염을 적용한다.
6. 대상에게 1.5초 물기 보호를 준다.

물기 성공 후에는 해당 표적을 감염된 동료로 처리한다. 강제 소음 10초가 남아 있으면
소음원 주변 배회로 돌아가고, 아니면 회복 동작이 끝난 뒤 즉시 순찰로 복귀한다.
물기가 빗나가거나 보호 상태로 막힌 경우에는 정상 추격 판단으로 복귀한다.

빌런에게는 물기 시각 사건과 감염을 모두 생성하지 않는다. 감지·추격은 정상적으로 유지한다.

### 10.4 끼임 복구

- 활성 원숭이는 각자 배정된 지점을 전역 후보로 공유하고 최근 방문 3곳을 제외한 뒤,
  다른 원숭이의 현재·예약 목적지에서 가장 먼 접근 가능한 방을 선택한다.
- 순찰 목적지는 서로 최소 8m 간격으로 예약하고, 후보가 부족할 때만 최근 방문 기억과
  간격 제한을 순서대로 완화한다.
- 이동 중 2.2m 안의 다른 원숭이와 분리 조향해 같은 선분 위 포개짐을 줄인다.
- 2초 동안 목적지 방향 이동량이 기준 이하이면 현재 목적지까지 경로를 재계산한다.
- 세 번 연속 실패하면 상태에 따라 다른 순찰 지점 또는 마지막 목격 위치 수색으로 전환한다.
- 이동 가능 영역을 이탈한 경우 가장 가까운 2D 웨이포인트로 서버가 재배치한다.
- 문 하나에 괴물이 과도하게 겹치지 않도록 로컬 회피 우선순위를 다르게 설정한다.

## 11. 강화 시스템

### 11.1 데이터

강화는 축 선택이 아니라 빌런 전용 미션(GDD §13.2) 누적 클리어 횟수로 진행된다.

- `VillainMissionClearCount` — 0~4 정수. 빌런에게 배정된 4개 미션 중 완료한 개수.
- 클리어 횟수 → 효과 매핑은 GDD §13.3 표를 그대로 따른다(1회 괴물 6마리,
  2회 8마리, 3회 감염 40초, 4회 감지 1.75m).

### 11.2 완료 처리

일반 미션 패널과 빌런 위장 미션은 같은 월드 좌표와 외형을 공유한다. 생존자에게는
개인·공용 시민 미션만, 실제 빌런 본인에게는 해당 위치의 위장 미션만 우선 노출한다.
두 변형은 서버 점유 상태를 따로 가지므로 같은 패널 앞에서 생존자와 빌런이 동시에 서로
다른 조작을 수행할 수 있다. 참가자가 한 명뿐인 연습 실행에서는 생존자 역할만 배정하고
빌런 미션은 상호작용 후보에서 제외한다.

1. 빌런 소유와 대상 스테이션을 검증한다.
2. 해당 미션이 이미 완료되지 않았는지 확인한다.
3. 서버가 생성한 같은 시드로 미션별 조작 세션을 시작한다(누르기·드래그·클릭 등).
4. 클라이언트 입력을 서버 세션에서 재현해 검증한다.
5. 서버 판정이 완료됐을 때만 `VillainMissionClearCount`를 1 올린다.
6. 새 누적 횟수에 대응하는 효과를 적용한다(§11.1).
7. 완료한 미션의 위장 대상 방에 영구 흔적을 남긴다.
8. 중요 사건 로그를 남긴다.
9. 빌런 UI를 갱신한다.

미완료 중단, 거리 이탈, 회의와 `Esc` 취소는 점유와 진행 상황을 모두 초기화한다. 완료한
미션은 같은 라운드에서 다시 수행할 수 없다. 클라이언트가 완료 여부를 직접 보내는 요청은
받지 않는다.

### 11.3 개체 수 효과

- 1회 클리어: 격리실 A에서 두 마리 생성 (4마리 → 6마리)
- 2회 클리어: 격리실 B에서 두 마리 생성 (6마리 → 8마리)
- 3초간 문 경고등과 경보를 재생한 뒤 활성화한다.
- 회의 호출이 경고 중 발생하면 남은 경고 시간을 보존한다.

이 효과는 특정 미션 하나에 고정되지 않는다. 4개 미션 중 어느 것이 1번째 또는 2번째로
완료되든 같은 효과가 적용된다(§11.1).

### 11.4 독성 효과 (3회 클리어)

이미 감염된 생존자의 제한시간은 변경하지 않는다. 3회째 미션을 완료한 이후 새로 물린
생존자에게만 40초 값을 적용한다.

## 12. 해독제 시스템

### 12.1 중앙 제어 PC 상태

```text
Idle
  → Analyzing (혈청 분석)
  → CodeIssued (코드 표시)
  → Idle (창을 닫음)
```

| 상태 | 조작 |
| --- | --- |
| Idle | 살아 있는 플레이어가 조회 시작 |
| Analyzing | 대기만 가능 |
| CodeIssued | 요청자에게만 코드 표시 |

코드는 서버가 생성하고 요청한 클라이언트에게만 전송한다. 발급 시 해당 플레이어의 이전 코드와
누적 오입 횟수를 초기화한다.

### 12.2 제작대 상태

```text
Idle
  → AwaitingCode (코드 입력 중)
  → Synthesizing (합성 진행)
  → Ready
  → Idle (누군가 획득)
```

| 상태 | 조작 |
| --- | --- |
| Idle | 유효한 코드 보유자가 입력 시작 |
| AwaitingCode | 5자리 입력, 오입 시 입력만 초기화 |
| Synthesizing | 남은 시간 확인만 가능 |
| Ready | 누구나 획득 가능 |

### 12.3 제작 시작 검증

- 살아 있는가?
- 유효한 배합 코드를 보유했는가?
- 제작대가 `Idle`인가?
- 상호작용 범위 안인가?

역할은 검사하지 않는다. 빌런은 감염되지 않지만 위장과 완성품 선점을 위해 생존자와 동일하게
제작할 수 있다(GDD §5.2, §14.3).

### 12.4 코드 입력 판정

- 입력한 코드의 정오는 **서버에서만** 판정한다. 정답을 클라이언트로 내려보내지 않는다.
- 오입 시 입력을 초기화하고 누적 오입 횟수를 1 올린다.
- 누적 오입이 최대치에 도달하면 코드를 무효화한다. PC에서 새로 발급받아야 한다.
- 코드 무효화는 소음 사건을 발생시키지 않는다. 감염 타이머와 이동 속도 감소가 이미 압박으로
  작동하고, 백신실은 마지막 피난처 역할을 유지해야 하기 때문이다.

### 12.5 획득

- 소지 슬롯이 비어 있어야 획득한다.
- 완성품 획득은 선착순 서버 판정이다.
- 완성품을 보관하는 별도의 칸은 두지 않는다.
- 아이템 소유권 변경은 사건 로그에 기록하지만 라운드 중 사용자에게 공개하지 않는다.

## 13. 감염 시스템

### 13.1 감염 인스턴스

```text
infectedPlayerId
durationAtBite
remainingTime
sourceMonsterId
startedServerTime
state
```

### 13.2 재물림

- `AliveInfected` 상태가 되면 `MonsterTarget`을 감지 불가로 전환한다.
- 괴물은 해당 생존자를 추격·물기하지 않고 물기 회복 뒤 강제 소음 배회 또는 순찰로 복귀한다.
- 치료가 완료되면 `MonsterTarget`을 다시 감지 가능으로 전환해 새 감염을 받을 수 있다.

### 13.2.1 감염 중 이동

- `AliveInfected` 상태에서는 이동 속도에 감염 배율을 적용한다(GDD §14.1).
- 유령 속도와 배터리 운반 속도가 함께 적용될 수 있는 경우 유령 속도를 우선한다.
- 치료가 완료되면 즉시 기본 속도로 복귀한다.

### 13.3 사망

타이머가 0에 도달하면 서버가 한 번만 다음을 수행한다.

1. 진행 중 행동 취소
2. 소지 해독제와 보유 배합 코드 소멸
3. `DeadGhost` 전환
4. 캐릭터 충돌과 생존자 시각 모델 비활성화
5. 유령 모델을 소유 클라이언트와 다른 유령에게만 활성화
6. 현실 생존자 수와 승패 확인

유령은 내부 벽 충돌을 통과하지만 연구소 실제 바닥 외곽에서 2m 확장한 전용 결계
(`x -42.5~38`, `y -25~32`)를 넘을 수 없다. 이동 목표를 먼저 결계 안으로 제한하고,
물리 틱 뒤 현재 위치도 다시 보정해 컴포넌트 실행 순서에 따른 한 프레임 이탈을 막는다.

## 14. 단서와 정보 시스템

### 14.1 단서 상태

- `Inactive`: 생성 전
- `ActiveUninspected`: 월드에 존재
- `ActiveInspected`: 한 명 이상 조사

조사 여부는 업적이나 결과 통계용이며 단서는 조사하지 않아도 보인다.

### 14.2 영구 단서

- 강화마다 연결된 단서 마커를 서버에서 즉시 예약하되, 완료 순간에는 아직 월드에
  활성화하지 않는다.
- 예약 마커의 관찰 반경 안에 살아 있는 생존자가 한 명이라도 있으면 공개를 보류한다.
  모든 생존자가 반경 밖으로 떠난 뒤 서버가 `ActiveUninspected`로 전환해 전원에게 복제한다.
  빌런과 `DeadGhost`는 관찰자로 계산하지 않는다.
- 보류 상태·완료 시각·수행자 신원은 클라이언트에 보내지 않는다. 따라서 같은 패널에서
  시민과 빌런이 동시에 미션을 해도 시민은 흔적이 생기는 순간으로 범인을 확정할 수 없다.
- 빌런 미션 6종(GDD §13.2)은 각각 독립된 위장 대상 방에 흔적을 남기므로, 완료한 미션
  수만큼 서로 다른 방에 흔적이 쌓인다.
- 단서는 라운드 종료까지 비활성화하지 않는다.
- 라운드 결과의 전체 흔적 수에는 아직 공개를 기다리는 예약 마커도 포함한다.

### 14.3 CCTV와 로그

- 프로젝트 50% 미만에는 단말기가 잠겨 있다.
- 50% 도달 사건으로 서버가 활성화한다.
- CCTV는 클라이언트 로컬 카메라를 전환하지만 관찰 가능한 플레이어 위치는 서버 동기 상태를 사용한다.
- 로그 조회 범위와 보존 시간은 밸런스 데이터에서 설정한다.

## 15. 회의 시스템

### 15.1 호출 검증

- 현재 상태가 `Exploration`인가?
- 호출자가 살아 있는가?
- 시작 후 탐색 시간 2분이 지났는가?
- 공용 쿨타임이 0인가?
- 사용 회의 수가 3회 미만인가?
- 이미 승패가 확정되지 않았는가?

여러 호출이 동시에 도착하면 서버가 먼저 받은 유효 요청 하나만 승인한다.

### 15.2 회의 진입

1. 게임 상태를 `MeetingDiscussion`으로 전환한다.
2. 진행 중 미션과 사용 행동을 취소한다.
3. 모든 월드 시계를 정지한다.
4. 살아 있는 참가자 목록과 토론 종료 시각을 전송한다.
5. 채팅 채널을 회의 참가자로 제한한다.

### 15.3 투표 집계

- 각 플레이어의 마지막 유효 표 한 개만 저장한다.
- 시간 안에는 표를 변경할 수 있다.
- 투표 종료 시 미투표자는 기권으로 바꾼다.
- 기권을 포함한 최고 득표가 둘 이상이면 퇴출하지 않는다.
- 기권이 단독 최고여도 퇴출하지 않는다.
- 플레이어 한 명이 단독 최고일 때만 퇴출한다.

### 15.4 회의 종료 보호

월드 재개 후 모든 살아 있는 플레이어에게 2초간 물기 보호를 준다. 괴물은 기존 위치에서 다시 판단하며 회의 직전 목표를 강제로 유지하지 않는다.

## 16. 승패 판정

승패 검사는 다음 사건 이후 실행한다.

- 미션 완료
- 투표 해결
- 생존자 사망
- 연결 종료 유예 만료
- 탐색 타이머 틱

### 16.1 우선순위

```text
1. 빌런 퇴출       → SurvivorWin
2. 진행률 100%     → SurvivorWin
3. 현실 생존자 0명 → VillainWin
4. 탐색 시간 0     → VillainWin
```

판정 함수는 이미 결과가 있으면 즉시 반환한다. 결과를 확정한 서버 틱 이후에는 월드 입력을 거부한다.

## 17. 연결 종료

### 17.1 호스트

- 세션 연결 종료를 전원에게 알린다.
- 현재 경기를 무효로 표시한다.
- 메인 메뉴 또는 재접속 안내 화면으로 이동한다.

### 17.2 생존자 클라이언트

- 30초간 `DisconnectedGrace` 상태
- 캐릭터는 이동·충돌·감지 대상에서 제외
- 재접속 시 기존 상태와 소유권 복원
- 만료 시 `DeadGhost`로 처리
- 미완료 미션은 동일 스테이션의 공용 복구 미션으로 전환

### 17.3 빌런 클라이언트

- 30초 유예 후 미복귀 시 생존자 승리
- 유예 중에는 빌런 능력을 사용할 수 없다.
