# 아트·오디오 에셋 가이드

> 문서 버전: 2.0  
> 기준 GDD: 2.0  
> 목표: 작은 팀이 일관된 2D 탑다운 연구소를 빠르게 제작하기 위한 아트 바이블과 에셋 목록

---

## 1. 시각 방향

### 1.1 스타일

- 2D 스프라이트, 어몽어스 계열 데포르메 캐주얼
- 맵은 위에서 내려다본 탑다운, 캐릭터는 정면 스프라이트 (§1.4 참조)
- 단순한 형태와 읽기 쉬운 실루엣
- 사실적인 재질보다 방 기능과 위험의 가독성 우선
- 직접적 고어보다 혈흔, 붉은 경고등, 어둠과 소리로 공포 표현
- 카메라 배율에서 보이지 않는 작은 디테일은 제작하지 않음

### 1.2 핵심 대비

- 차가운 청록·청색 연구소 환경
- 따뜻한 주황 비상등
- 빌런 강화와 감염은 강한 적색
- 상호작용 가능 오브젝트는 약한 청록 발광

### 1.3 권장 팔레트

| 용도 | 색상 예시 |
| --- | --- |
| 배경 암부 | `#111820` |
| 금속 벽 | `#35434C` |
| 의료 백색 | `#C8D4D8` |
| 시스템 청록 | `#34C6C8` |
| 전력 노랑 | `#E7B84B` |
| 경고 주황 | `#E87532` |
| 감염 적색 | `#D63B42` |
| 빌런 자주 | `#8C4EC7` |

색상은 방향이며 최종 머티리얼과 조명에서 명도 대비를 확인한다.

### 1.4 시점과 캐릭터 표현

**맵은 탑다운, 캐릭터는 정면 스프라이트를 쓴다.** 어몽어스와 같은 조합이다. 시점이 엄격히
일치하지 않지만, 위에서 본 캐릭터(머리와 어깨만 보임)보다 정면 캐릭터가 색과 형태를 훨씬 잘
전달한다. 정체를 숨기는 게임에서 "누가 누군지"를 즉시 알아야 하므로 이 쪽을 택한다.

| 항목 | 기준 |
| --- | --- |
| 캐릭터 등신 | 2등신 (머리 1 : 몸 1) |
| 캐릭터 화면 크기 | 약 1.2 × 1.6m 상당 (그리드 셀 0.5m 기준 약 2.4 × 3.2셀) |
| 방향 표현 | 좌우 반전 + 4방향 스프라이트 (상·하·좌·우) |
| 애니메이션 | 프레임 애니메이션. 스켈레톤·리깅 없음 |
| 괴물 톤 | 데포르메하지 않음 (§3.1 참조) |

2D로 가면서 3등신 제약이 사라졌다. 쿼터뷰에서 2등신이 문제였던 이유는 큰 머리가 몸통을 가려
진행 방향이 안 보이는 것이었는데, 탑다운에서는 캐릭터를 정면 스프라이트로 그리므로 해당하지
않는다. 어몽어스와 같은 2등신을 쓴다.

스켈레톤과 리타게팅 문제도 사라졌다. 3D에서는 휴머노이드 리그를 유지해야 기성 애니메이션을
쓸 수 있었지만, 2D는 프레임을 직접 그리므로 그 제약이 없다. 대신 방향별 스프라이트를 따로
그려야 해서 총 작업량은 비슷하다.

### 1.5 픽셀 기준

| 항목 | 값 |
| --- | --- |
| Pixels Per Unit | 32 |
| 1 월드 유닛 | 1m |
| 그리드 셀 (0.5m) | 16픽셀 |
| 캐릭터 스프라이트 | 약 40 × 52픽셀 |
| 타일 (1m) | 32 × 32픽셀 |
| 필터 모드 | Point (no filter) — 픽셀아트인 경우 |
| 압축 | 스프라이트는 무압축 또는 고품질 |

Pixels Per Unit을 32로 고정하면 길찾기 그리드 셀(0.5m = 16px)과 타일이 정수로 맞아 어긋남이
생기지 않는다. 이 값을 바꾸면 모든 스프라이트를 다시 임포트해야 하므로 초기에 확정한다.

## 2. 캐릭터 에셋

### 2.1 직원

MVP는 기본 스프라이트 한 세트를 공유하고 색상만 바꾼다. 비율은 §1.4의 2등신 기준을 따른다.

- 실험복 또는 회사 작업복을 큰 덩어리로 단순화
- 몸통 색상 6종. **색상 팔레트만 교체**해 6명을 만든다 (스프라이트 재사용)
- 색맹 대응으로 몸통에 번호 또는 패턴을 함께 표시 (GDD §21)
- 손전등은 별도 스프라이트가 아니라 2D 라이트로 표현
- 배터리·해독제 소지는 캐릭터 위 작은 아이콘으로 표시
- 유령은 같은 스프라이트의 반투명 버전

#### 스프라이트 목표

| 항목 | 기준 |
| --- | --- |
| 캐릭터 스프라이트 | 약 40 × 52픽셀 (§1.5) |
| 방향 | 4방향 (상·하·좌·우). 좌우는 반전으로 재사용 가능 |
| 색상 변형 | 팔레트 스왑 또는 머티리얼 색조 (스프라이트 복제 금지) |
| 아틀라스 | 캐릭터 전체를 하나의 Sprite Atlas로 묶는다 |
| 필터 | Point, 압축 없음 |

색상 변형을 스프라이트 복제로 만들면 6배 용량과 6배 수정 비용이 든다. 팔레트 스왑이나
`SpriteRenderer.color` 색조로 처리한다.

### 2.2 직원 애니메이션

프레임 애니메이션이다. 방향별로 필요하지만 4방향 전부를 처음부터 만들지 않는다.

| 애니메이션 | MVP 프레임 | 방향 |
| --- | ---: | --- |
| Idle | 2 | 4방향 |
| Walk | 4~6 | 4방향 |
| Interact | 2~3 | 하단만 (미션 중 방향 고정) |
| Carry (Idle/Walk) | Walk 재사용 + 아이콘 | 4방향 |
| Bitten | 2 | 무방향 (제자리 연출) |
| UseAntidote | 3 | 하단만 |
| Death | 3~4 | 무방향 |

Ghost는 Idle/Walk를 반투명으로 재사용한다.

우선순위는 **Idle → Walk → Interact** 순이다. 이 셋만 있어도 플레이가 성립한다.
나머지는 임시로 Idle을 재생해도 무방하다.

## 3. 원숭이 괴물

### 3.1 형태

괴물은 직원과 달리 데포르메하지 않는다. 3등신 직원과 사실적 비율의 괴물을 한 화면에 두는 톤
충돌은 의도된 것이다. 귀여운 캐릭터 사이에 이질적인 포식자가 있을 때 공포가 더 커지며, 탑뷰에서
플레이어와 위험을 즉시 구분하게 해준다.

- 일반 원숭이보다 길고 불균형한 팔
- 직원보다 낮고 옆으로 넓은 실루엣 — 등신을 맞추지 않는다
- 탑다운에서 직원 스프라이트와 한눈에 구분되는 형태
- 붉은 눈 또는 목 주변 RX-9 흔적
- 직접적인 장기 노출보다 변형된 피부와 털 표현
- 단계가 올라가도 스프라이트 교체보다 색조·VFX 강도 변화 사용

톤 충돌이 공포가 아니라 어색함으로 읽히면, 괴물을 데포르메하는 대신 조명·VFX·사운드를 먼저
조정한다. 두 방향을 섞으면 양쪽 다 약해진다.

### 3.2 기술 기준

| 항목 | 기준 |
| --- | --- |
| 스프라이트 | 약 56 × 40픽셀 (직원보다 넓고 낮게) |
| 방향 | 4방향 |
| 아틀라스 | 괴물 전체를 하나의 Sprite Atlas로 |
| 콜라이더 | 이동용 CircleCollider2D + 물기 판정 범위 |
| 정렬 | 직원과 같은 Sorting Layer, Y 좌표 기준 정렬 |

### 3.3 애니메이션

| 애니메이션 | MVP 프레임 | 방향 |
| --- | ---: | --- |
| Idle | 2 | 4방향 |
| Walk | 4 | 4방향 |
| FastRun | 4 | 4방향 (Walk 재생 속도 상향으로 대체 가능) |
| Listen | 2 | 4방향 |
| Bite | 3 | 4방향 |
| CageExit | 3 | 무방향 |

Search와 Recover는 Idle을 재사용한다.

물기 애니메이션은 판정 프레임을 Animation Event로 결정하지 않고 서버 타이밍 데이터와 맞춘다.
2D 프레임 애니메이션에서도 이 원칙은 같다. 연출과 판정을 분리한다.

## 4. 타일셋과 환경

### 4.1 타일셋

Unity Tilemap을 사용한다. 타일 하나는 1m(32픽셀)다.

- 바닥 타일 (연구소 리놀륨, 금속 그레이팅, 백신실 타일)
- 벽 타일: 직선, 코너(내·외), T자, 십자
- 문 타일: 자동문, 격리문, 비상구
- 유리벽 (격리실 강화 유리 포함)
- 기둥
- 환풍구 (붉은 연기 단서 위치)
- 파이프·케이블 트레이 (바닥 장식 레이어)

벽 타일은 **Rule Tile**로 만들어 자동 연결되게 한다. 수동으로 코너를 배치하면 맵 수정 비용이
커진다.

타일맵은 두 레이어로 나눈다. `Floor`(충돌 없음)와 `Walls`(CompositeCollider2D). 길찾기
그리드는 `Walls` 레이어를 입력으로 굽는다 (`map-level-design.md` §11).

### 4.2 조명

URP 2D Renderer의 2D 라이트를 사용한다.

| 용도 | 라이트 종류 |
| --- | --- |
| 전체 기본광 | Global Light 2D (프로젝트 단계에 따라 강도 변화) |
| 손전등 | Spot Light 2D (원뿔, 마우스 방향 추적) |
| 비상등·유도등 | Point Light 2D, 낮은 강도 |
| 스피커 LED·상태등 | Sprite 자체 발광 (라이트 아님) |

스프라이트에 노멀맵을 만들지 않는다. 2D 라이트는 노멀맵 없이도 동작하며, 픽셀 스타일에서는
평면 조명이 오히려 자연스럽다.

**어둠 표현은 Global Light 강도로 조절한다.** 프로젝트 0%에서 어둡게 시작해 25/50/75/100%
단계마다 밝아진다 (GDD §9.2). 조명 갯수를 늘리는 대신 전역 강도를 올리는 쪽이 성능에 유리하다.

## 6. 머티리얼과 텍스처

- URP Lit 기반을 기본으로 한다.
- 불필요한 투명 머티리얼을 줄인다.
- 환경은 타일러블 금속, 플라스틱, 고무, 유리 재질을 공유한다.
- 작은 프롭은 아틀라스를 사용한다.
- 방 구분은 별도 모델보다 머티리얼 색, 표지, 데칼로 해결한다.
- 탑뷰에서 읽히지 않는 4K 텍스처는 사용하지 않는다.
- 원본 작업 파일과 Unity용 출력 파일을 분리한다.

### 권장 출력

- 모델: FBX
- 텍스처: PNG 또는 TGA
- 일반 맵: Linear import
- 컬러·UI: sRGB import
- 오디오 원본: WAV
- 런타임 압축: Unity Import Settings에서 용도별 적용

## 8. 조명과 후처리

### 8.1 조명

- 환경 기본광으로 완전한 검정을 피한다.
- 정적 환경은 베이크 조명 또는 혼합 조명을 우선한다.
- 손전등, 비상등과 강화 단서는 동적 조명을 제한적으로 사용한다.
- 캐릭터 얼굴보다 실루엣과 바닥 이동 경로가 우선이다.

### 8.2 후처리

- 약한 Bloom
- 약한 Vignette
- 색보정
- 선택적 Film Grain
- Motion Blur는 기본 비활성화 권장
- 감염 효과는 접근성 설정으로 낮출 수 있음

## 9. UI 아트

- 의료 단말과 비상 시스템을 연상시키는 직사각형 패널
- 본문은 한글 가독성 우선
- 아이콘은 24px에서도 형태가 구분돼야 함
- 모든 플레이어 색상에 번호 또는 기호 병행
- 미션 UI는 월드 장비의 색과 형태를 이어받음
- 빌런 전용 UI는 자주·적색이지만 외부 캐릭터 연출은 정상 미션과 같음

UI 세부 화면과 상태는 `ui-ux-design.md`를 따른다.

## 10. 오디오 디자인 원칙

소리는 분위기뿐 아니라 실제 게임 정보다.

1. 괴물 반응을 일으키는 게임 소음과 분위기 소리를 구분한다.
2. 게임 소음은 발생 원인과 위치를 학습할 수 있어야 한다.
3. 괴물의 접근은 화면 밖에서도 판단 가능해야 한다.
4. 음악이 발소리, 경보와 감염 타이머를 가리지 않는다.
5. 중요한 소리는 방향 표시와 자막을 지원한다.

## 11. 오디오 믹서 구조

```text
Master
├── Music
├── Ambience
├── SFX
│   ├── Player
│   ├── Monster
│   ├── Mission
│   ├── World
│   └── Danger
└── UI
```

회의 중에는 월드 SFX와 Ambience를 낮추되 완전히 끄지 않고 정지된 연구소의 잔향을 약하게 남긴다. `Danger`와 UI는 별도 볼륨 조절을 제공하되 0으로 만들 경우 시각 경고가 반드시 켜져야 한다.

## 13. 공간 음향 규칙

- 괴물, 미션, 스피커, 문은 공간 음향(Spatial Blend 3D)으로 재생한다.
  2D 게임이지만 AudioSource의 공간 설정은 그대로 쓸 수 있고, 소리 방향 판단에 필요하다.
- UI와 개인 감염 심장 박동은 Spatial Blend 2D로 재생한다.
- 벽 하나를 사이에 둔 소리는 저역 통과와 볼륨 감소를 적용할 수 있다.
- 실제 괴물 AI의 소음 반경과 플레이어가 듣는 오디오 감쇠는 별도 데이터지만 모순되지 않게 조정한다.
- 스피커 소리는 방 바깥에서도 방향을 찾을 수 있어야 한다.
- 같은 효과음이 반복될 때 피치와 샘플 변형으로 피로를 줄인다.

## 15. 외부 에셋 규칙

- 구매·무료 여부와 관계없이 상업적 사용 가능 여부를 확인한다.
- 원본 링크, 제작자, 라이선스, 수정 여부를 기록한다.
- 서로 다른 스타일의 에셋은 머티리얼과 비율을 통일한 뒤 사용한다.
- 외부 패키지 전체를 `Assets/_Project` 안으로 이동하지 않는다.
- 샘플 씬과 미사용 고해상도 파일은 프로젝트에 포함하지 않는다.
- 라이선스 전문 또는 고지 의무는 `THIRD_PARTY_NOTICES.md`에 남긴다.
