# 아트·오디오 에셋 가이드

> 문서 버전: 2.7
> 기준 GDD: 1.1
> 목표: 작은 팀이 일관된 2D 탑다운 연구소를 빠르게 제작하기 위한 아트 바이블과 에셋 목록

## 1. 시각 방향

### 1.1 스타일

- 스타일라이즈드 2D 탑다운 일러스트
- 단순한 형태, 굵은 외곽선과 읽기 쉬운 실루엣
- 사실적인 재질보다 방 기능과 위험의 가독성 우선
- 직접적 고어보다 혈흔, 붉은 경고등, 그림자와 소리로 공포 표현
- 바닥과 방 배치는 위에서 내려다본 평면으로 표현한다
- **캐릭터는 정수리가 아니라 오른쪽을 보는 측면 프로필로 그린다.** 카메라는 직교·비회전이고
  몸통도 회전하지 않으므로, 위에서 본 형태보다 측면 실루엣이 훨씬 잘 읽힌다. 왼쪽 방향은
  좌우 플립으로 처리하므로 한 방향만 그린다
- 바닥은 위에서, 캐릭터와 벽 설비는 정면·측면으로 그리는 혼합 시점을 의도적으로 쓴다.
  카툰 소셜 디덕션 게임의 관례이며 원근 왜곡을 흉내 내지 않는다
- 직교 카메라와 게임 좌표는 유지한다. 각 방·복도의 화면 위쪽 바닥 경계에서 벽 정면을
  아래로 `2.45m` 내려 표시한다. 화면 아래쪽 경계는 얇은 상단 단면으로 남겨 같은 평면을
  두 방향 입면으로 중복 표현하지 않는다. 위·아래 통로의 문은 선이 아니라 상단이 벽 경계에
  고정된 높이 `1.65m` 직사각형 정면 패널로 표시하고, 좌우 통로 문은 측면 두께를 표시한다.
  바닥형 가구는 footprint 아래쪽을 발로 삼아 `footprint.y × 0.55 + 0.85m` 높이로
  표시한다. 그림자는 발 오른쪽 아래로 `0.16m` 옮겨 납작하게 만들며, 캐릭터·원숭이·
  가구는 발 Y 기준으로 앞뒤 정렬한다. 문 패널과 문틀은 정면 두께를 한 단계 강조한다
- 다른 소셜 디덕션 게임의 캐릭터·방·아이콘·로고를 복제하지 않고, RX-9 연구소 고유의
  방호복·원숭이 실루엣과 색 체계를 사용. 단 UI의 **형태 문법**(둥근 두꺼운 버튼,
  굵은 외곽선 글자, 하이컨트라스트 플랫 패널)은 카툰 소셜 디덕션 게임의 가독성
  관행을 따른다 (`ui-ux-design.md` §15.3). 복제하지 않는 것은 고유 자산이고,
  따르는 것은 가독성 관행이다
- 직교 카메라 거리에서 보이지 않는 작은 디테일은 제작하지 않음

### 1.2 핵심 대비

- 차가운 청록·청색 연구소 환경
- 따뜻한 주황 비상등
- 빌런 강화와 감염은 강한 적색
- 상호작용 가능 오브젝트는 약한 청록 발광

## 2. 캐릭터 에셋

### 2.1 직원

MVP는 기본 바디 한 개를 공유한다.

- 실험복 또는 회사 작업복 실루엣, 오른쪽을 보는 측면 프로필
- 멀리서도 번호가 보이는 등·가슴 표식
- 손전등 장착 지점
- 배터리 운반 소켓
- 해독제 사용 손 소켓
- 유령용 단순 반투명 버전

**몸통은 회색조로 그린다.** 플레이어 색 6종은 런타임에
`SpriteRenderer.color` 틴트로 곱해 넣으므로, 색을 칠하면 로비 색상이 먹지 않는다.
흰색을 기준으로 음영만 회색으로 넣는다. 방호복 밝기는 80~100%를 유지한다.
어두운 회색으로 그리면 곱셈 결과가 눌려 6색이 서로 구분되지 않는다.

**바이저와 장비 윤곽은 같은 그림 안에 어둡게 그린다.** 곱셈 틴트는 어두운 화소를
어둡게 남기므로, 검은 바이저·외곽선·벨트는 색을 바꿔도 형태가 그대로 살아남는다.
별도 레이어로 분리하지 않는다.

### 2.2 캐릭터 스프라이트 규격

| 항목 | 값 |
| --- | --- |
| 캔버스 | 1254 × 1254 px 정사각, 배경 투명, PNG RGBA 8bit |
| Pixels Per Unit | 1024 (1254px ≈ 월드 1.22m) |
| 피벗 | Center. 캐릭터를 캔버스 정중앙에 배치 |
| 방향 | 오른쪽 바라보기 한 방향만 |
| 프레임 | 정지 1장 + 걷기 4장 |
| 비율 | 키:폭 약 1:0.75. 캔버스를 꽉 채우지 않고 여백을 둔다 |

걷기 4프레임은 접지A → 모음 → 접지B → 모음 순환이고, 모음 프레임을 두 번 재사용하므로
실제로 그리는 그림은 **정지·접지A·모음·접지B 4장**이다. 상하 바운스는
`PlayerMotionFeel`이 절차적으로 만들므로 프레임에 그려 넣지 않는다.

프레임을 넘기는 것은 `CharacterWalkAnimator`이며, 시간이 아니라 **이동 거리**를 센다.
2.244m마다 한 바퀴를 돌아 `PlayerMotionFeel`의 바운스 주기와 맞물리므로, 순찰과 추격처럼
속도가 다른 상황에서도 발 구르는 속도가 저절로 따라간다.

원숭이도 같은 규격이지만 **몸통은 풀컬러로 그린다.** 상태(순찰·조사·추격·물기)는 몸 전체가
아니라 이마의 RX-9 표식만 색을 바꾸므로(§3.1), 회색조로 그릴 이유가 없다.

#### 파일 이름

아래 이름 그대로 `Assets/_Project/Art/Sprites/Characters/`에 넣으면 코드 수정 없이 붙는다.
걷기 3장은 없어도 씬 생성이 막히지 않으며, 세 장이 모두 갖춰졌을 때만 순환이 시작된다.

| 프레임 | 직원 | 원숭이 |
| --- | --- | --- |
| 정지 | `S_Player_Survivor.png` | `S_Monkey_Mutant.png` |
| 접지A | `S_Player_Survivor_WalkA.png` | `S_Monkey_Mutant_WalkA.png` |
| 모음 | `S_Player_Survivor_WalkPass.png` | `S_Monkey_Mutant_WalkPass.png` |
| 접지B | `S_Player_Survivor_WalkB.png` | `S_Monkey_Mutant_WalkB.png` |

GIF는 쓰지 않는다. Unity가 임포트하지 못한다. 네 장 모두 낱장 PNG로 넣고,
네 장의 캔버스 크기와 캐릭터 위치를 정확히 맞춰 프레임이 바뀔 때 튀지 않게 한다.

#### 방향과 회전

본체는 오른쪽 보기 한 방향만 그린다. 왼쪽으로 이동하면 코드가 `flipX`로 뒤집는다.
본체 스프라이트 자체를 회전하지는 않으며, 조준 방향으로 도는 것은 `AimPivot`과
손전등뿐이다. 4방향·8방향 프레임은 MVP 범위가 아니다.

#### 조명 유의

월드 전역광이 매우 낮고(`SO_WorldLightingBalance_Default`) 스프라이트는 URP 2D Lit이다.
새까맣게 그린 부분은 화면에서 사라진다. 중간~밝은 명도를 유지하고, 어둠은 조명이 만들게 둔다.

### 2.2 직원 애니메이션

## 3. 원숭이 괴물

### 3.1 형태

- 일반 원숭이보다 길고 불균형한 팔
- 낮은 자세에서도 탑뷰 실루엣이 직원과 명확히 다름
- 붉은 눈 또는 목 주변 RX-9 흔적
- 직접적인 장기 노출보다 변형된 피부와 털 표현
- 단계가 올라가도 모델 교체보다 머티리얼·VFX 강도 변화 사용

현재 프로토타입 본체는 `S_Monkey_Mutant.png`를 사용한다. AI 상태 색은 몸 전체를
바꾸지 않고 이마의 RX-9 표시만 바꿔 원숭이 외형과 상태 정보를 분리한다.
따라서 몸통은 회색조가 아니라 풀컬러로 그린다(§2.2).
직원과 같이 오른쪽 보기 측면 프로필 한 방향만 그리고, 왼쪽 이동은
`CharacterWalkAnimator`가 `flipX`로 뒤집는다. 몸통을 회전시키지는 않으며
시야·물기 판정은 계속 별도의 논리 방향 벡터를 쓴다.

### 3.2 기술 기준

| 항목 | 기준 |
| --- | --- |
| 본체 프레임 | §2.2 캐릭터 스프라이트 규격과 동일 (1254×1254px, PPU 1024) |
| 방향 | 오른쪽 보기 한 방향. 왼쪽은 `flipX` |
| 색상 | 몸통 풀컬러. 상태 색은 이마 RX-9 표식만 |
| 레이어 | 몸은 한 장. 눈·RX-9 발광은 코드가 별도 스프라이트로 얹는다 |
| 콜라이더 | `CapsuleCollider2D` 이동 영역 + 서버 물기 거리 판정 |

### 3.3 애니메이션

- Idle
- Walk
- FastRun
- Listen
- Search
- Turn
- Bite
- Recover
- CageExit

MVP에서 실제로 그리는 것은 §2.2의 정지·걷기 4프레임뿐이다. 위 목록은 이후 확장 목표이며,
그때까지 추격·물기 같은 상태는 이마 RX-9 표식 색과 이동 속도로 구분한다.

물기 애니메이션은 판정 프레임을 Animation Event 자체로 결정하지 않고 서버 타이밍 데이터와 맞춘다.

## 4. 모듈형 2D 환경 키트

### 4.1 구조물

- 1m, 2m, 4m 벽 단면 스프라이트
- 안쪽·바깥쪽 코너와 문틀
- 유리벽·격리실 강화 유리 오버레이
- 바닥 타일 2m, 4m와 방별 데칼
- 낮은 기둥과 반투명 상부 장식
- 환풍구, 파이프, 케이블 트레이
- 자동문·격리문 애니메이션
- 비상구·옥상문 표식

피벗과 그리드는 1m 단위를 기본으로 통일한다.

### 4.1.1 현재 바닥 아트와 회색상자 표현

바닥과 벽은 완성 PNG가 있으면 이를 우선 사용하고, 빠졌을 때만 `FirstPlayableBuilder`가
절차적으로 만든 회색상자 스프라이트로 되돌아간다. 공용 설비·기본 가구·실험 장비·
보안실·전력실·입원실·격리실·액체 보관실 장비와 백신실 일부 장비도 완성 PNG를 우선 사용하고,
아직 제작하지 않은 나머지 방별 프롭만
절차형 스프라이트를 사용한다.
예전에는 흰 정사각형 한 장(`S_UnitSquare`)을 늘려 전부 그렸기 때문에 방·벽·프롭이 모두
같은 네모로 보였다. 지금은 형태별로 그리는 방식을 나눈다.

| 대상 | 스프라이트 | 그리는 방식 |
| --- | --- | --- |
| 방 바닥 | `Resources/Environment/Floors/T_Floor_{RoomId}` | 4m 반복. 10개 방마다 색·재질·패널 구조가 다른 전용 1024px 타일 |
| 복도 바닥 | `T_FloorTile_Corridor` | 2m 타일 반복. 체결식 금속 패널 |
| 벽 단면 | `T_WallSection` | 9-slice. 어두운 캡과 청록 체결부 |
| 벽 정면 | `T_WallFace` | 9-slice. 밝은 상단 립과 어두운 걸레받이. 런타임에 방별 저채도 벽지와 패널 무늬를 겹침 |
| 자동문 패널 | `T_DoorPanel` | 9-slice. 의료 백색 압력판과 청록 밀폐선 |
| 자동문 문틀 | `T_DoorFrame` | 9-slice. 벽과 이어지는 어두운 구조재 |
| 방·출입구 이름판 | `T_RoomSignPanel` | 9-slice. 글자는 굽지 않고 `SCDream6`으로 동적 표시 |
| 바닥 유도 데칼 | `S_FloorGuideDecal` | 투명 RGBA. 복도 진행 방향으로 회전·좌우 반전 |
| 천장 조명 패널 | `S_CeilingLightPanel` | 투명 RGBA·Unlit. 방마다 2개 배치 |
| 비상 경고등 | `S_EmergencyBeacon` | 투명 RGBA·Unlit. 방마다 상단 1개 배치 |
| 벽 모니터 | `S_WallMonitor` | 투명 RGBA·Unlit. 빌더용 공용 대체 슬롯이며 런타임에는 방별 시스템 패널로 교체 |
| 소화기 | `S_FireExtinguisher` | 투명 RGBA. 빌더용 공용 대체 슬롯이며 방별 벽 장식 적용 시 숨김 |
| 쓰레기통 | `S_TrashBin` | 투명 RGBA. 방마다 바닥 1개 배치 |
| 비상전화 | `S_EmergencyPhone` | 투명 RGBA. 빌더용 공용 대체 슬롯이며 방별 벽 장식 적용 시 숨김 |

방별 벽지는 공통 금속 재질 위에만 얕게 겹쳐 연구소 통일감을 유지한다. 백신실·입원실은
청록/녹색, 실험실은 청색/보라색, 격리실은 적색 위험 띠, 보관실은 냉각 청색, 보안실은
고채도 청록, 전력실은 황색 위험 띠를 사용한다. 벽걸이 장식은 시스템 패널 1개를 기본으로 하고
벽 폭이 충분할 때만 CCTV·전자시계·상태계 중 방 기능에 맞는 1개를 추가한다.

방 바닥은 공용 회색 타일에 색만 곱하지 않는다. 백신실 A는 민트 육각 밀폐판, 백신실 B는

  Unlit 외형을 쓰고 기존 벽면 설치 종류·충돌체·상태등은 유지한다.
- 격리실 연출은 `tools/make_quarantine_vfx_assets.py`가 경고등·봉쇄 바닥 격자·깨진 강화유리·
  구역 번호의 비율과 투명 여백을 통일한다. 번호는 생성 이미지에 맡기지 않고 `SCDream6`으로
  `01 → 02 → 03`을 정확히 합성하며, 바닥 격자·번호·경고등은 Unlit으로 표시한다.
- 액체 보관실 핵심 장비는 `tools/make_storage_equipment_assets.py`가 세로 극저온 탱크·정사각형
  시료 드럼·초장형 결빙 배관·벽면 온도 단말기·냉각수 매니폴드의 비율과 투명 여백을 통일한다.
  온도 단말기만 Unlit 외형을 쓰고 기존 `Footprint`·충돌체·벽면 설치 종류·상태등은 유지한다.
- 액체 보관실 잔여 장비와 백신실 시작 장비는 `tools/make_storage_completion_assets.py`가 세로
  냉장 선반·단열 팔레트·바닥 배수구·바이알 랙·초광폭 무균 작업대의 비율과 여백을 통일한다.
  배수구는 기존 `FloorDecal`, 나머지는 기존 `Footprint`와 충돌체를 그대로 유지한다.
- 백신실 전용 보조 장비는 `tools/make_vaccine_support_assets.py`가 벽면 제독 세척대·세로 PPE
  디스펜서·무균 바닥 구역·주입기 시험기·혼합 작업대의 해상도와 투명 여백을 통일한다.
  바닥 구역과 시험기만 Unlit 외형을 쓰고 별도 `Light2D`는 만들지 않는다.
- 실험실 A 전용 설비는 `tools/make_lab_a_support_assets.py`가 세로 시료 랙·벽면 공조 배출구·
  검체 스캐너·비상 세안기·초광폭 천장 서비스 레일의 비율과 여백을 통일한다. 공조 배출구는
  실험실 B와 공유하고 스캐너만 Unlit 외형으로 표시한다.
- 실험실 A 마지막 바닥 데칼과 실험실 B 핵심 설비는 `tools/make_lab_b_core_assets.py`가 화학
  유출 표시·세로 백업 서버 랙·시료 밀봉기·패키지 스캐너·밀폐 상자 더미의 비율과 여백을
  통일한다. 서버 랙과 스캐너만 Unlit 외형을 쓰고 별도 `Light2D`는 만들지 않는다.

### 4.1.2 최종 아트로 교체하기

바닥과 벽은 `FirstPlayableBuilder`가 `Art/Sprites/Environment/`의 PNG를 먼저 읽고, 없으면
`Art/Sprites/Generated/`의 절차형 에셋을 읽는다. 프롭 112개는 각각
`EnvironmentPropSlot`을 갖고 있고, 여기에 `AssetKey`, `Footprint`,
`MountKind`, `ReplacementAnchor`, `SetPlaceholderVisible()`가 들어 있다. 최종 스프라이트나
프리팹은 `ReplacementAnchor`에 붙이고 회색상자는 `SetPlaceholderVisible(false)`로 끈다.

공용 설비 4종·기본 가구와 전용 장비·바닥 연출 107개·구조물은 빌더가 완성 스프라이트를 바로 교체한다. 나머지 방별 프롭은
배치 정보만 준비된 상태이며, 그림을 넣기 시작하는 시점에 `AssetKey → 스프라이트`
카탈로그 ScriptableObject와 이를 순회하는 리졸버를 만들어야 한다.

## 6. 스프라이트와 머티리얼

- URP의 Sprite 호환 셰이더를 기본으로 한다.

- 원본 작업 파일과 Unity용 PNG 출력 파일을 분리한다.

### 권장 출력

- 스프라이트: 투명 PNG
- 색상 마스크·UI: sRGB import
- 마스크·노멀맵: 용도에 맞춰 Linear import
- 오디오 원본: WAV
- 런타임 압축: Unity Import Settings에서 용도별 적용

## 9. UI 아트

- 모서리를 둥글린 두꺼운 패널과 버튼. 반경과 크기는 `ui-ux-design.md` §15.3을 따름
- 본문은 한글 가독성 우선. 굵은 산세리프와 검정 외곽선을 기본으로 씀
- 아이콘은 24px에서도 형태가 구분돼야 하고 얇은 선 대신 채운 면을 씀
- 모든 플레이어 색상에 번호 또는 기호 병행
- 미션 UI는 월드 장비의 색을 이어받되 패널 형태는 위 공통 문법을 씀
- 빌런 전용 UI는 자주·적색이지만 외부 캐릭터 연출은 정상 미션과 같음
- `Resources/UI/T_LaboratoryMap.png`는 실제 `10_Laboratory` 씬의 방·복도 실루엣을 그대로
  정리한 1495×1052 정적 지도다. 생성 이미지 안에는 글자와 마커를 넣지 않고 방 이름과
  본인 위치 점을 Unity UI에서 겹쳐 그린다
- `Resources/UI/T_MeetingChatPanel.png`는 1672×941 불투명 RX-9 보안 메신저 패널이다.
  왼쪽 참가자 영역과 오른쪽 대화 영역만 이미지에 두고, 한글·이름·말풍선·버튼은 런타임 UI로
  겹쳐 그린다. 원본은 `source-assets/Textures/ImageGen/T_MeetingChatPanel_Source.png`에 둔다.
  생성 지시는 "청흑색 생물 연구소, 좌측 참가자 구역, 우측 빈 대화 구역, 청록 모서리 조명,
  주황 비상 강조, 글자·인물·말풍선·로고 없음, 게임 월드를 완전히 가리는 불투명 16:9 UI"다.

의료 단말을 연상시키는 직사각형 패널은 1.5까지의 방향이었고, 어두운 월드에서 글자가
읽히지 않아 1.6에서 위 문법으로 교체했다. 월드 장비 자체는 계속 직사각형 산업 디자인을
유지하므로 UI와 월드는 의도적으로 다른 형태 언어를 쓴다.

### 9.1 폰트 에셋

| 항목 | 값 |
| --- | --- |
| 위치 | `game/Assets/_Project/Art/Fonts/` |
| 라이선스 | 재배포 가능한 것만 사용 (OFL 등). 상업 폰트와 OS 번들 폰트는 저장소에 넣지 않음 |

## 10. 오디오 디자인 원칙

소리는 분위기뿐 아니라 실제 게임 정보다.

1. 괴물 반응을 일으키는 게임 소음과 분위기 소리를 구분한다.
2. 게임 소음은 발생 원인과 위치를 학습할 수 있어야 한다.
3. 괴물의 접근은 화면 밖에서도 판단 가능해야 한다.
4. 음악이 발소리, 경보와 감염 타이머를 가리지 않는다.
5. 중요한 소리는 방향 표시와 자막을 지원한다.

## 13. 공간 음향 규칙

- 괴물, 미션, 스피커, 문은 XY 위치를 사용하는 공간 AudioSource를 사용한다.

- 같은 효과음이 반복될 때 피치와 샘플 변형으로 피로를 줄인다.

| --- | --- | --- |
| Sprite | `S_` | `S_Player_Body`, `S_Monkey_Idle_N` |
| Sprite Atlas | `SA_` | `SA_Laboratory`, `SA_Characters` |
| Material | `M_` | `M_LabWall_White` |
| Texture | `T_` | `T_Monkey_BaseColor` |
| Animation | `A_` | `A_Monkey_Bite` |
| Animator Controller | `AC_` | `AC_Player` |
| VFX Prefab | `VFX_` | `VFX_RedVentSmoke` |
| Audio Clip | `SFX_` / `AMB_` / `MUS_` | `SFX_Monkey_Bite_01` |
| Audio Mixer | `MX_` | `MX_Master` |

버전과 `final`을 파일명에 붙이지 않는다. 변경 이력은 Git으로 관리한다.

## 15. 외부 에셋 규칙

- 구매·무료 여부와 관계없이 상업적 사용 가능 여부를 확인한다.
- 원본 링크, 제작자, 라이선스, 수정 여부를 기록한다.
- 서로 다른 스타일의 에셋은 머티리얼과 비율을 통일한 뒤 사용한다.
- 외부 패키지 전체를 `Assets/_Project` 안으로 이동하지 않는다.
- 샘플 씬과 미사용 고해상도 파일은 프로젝트에 포함하지 않는다.
- 라이선스 전문 또는 고지 의무는 `THIRD_PARTY_NOTICES.md`에 남긴다.

## 16. 에셋 제작 우선순위

1. 플레이어 캡슐과 괴물 캡슐로 그레이박스 검증
2. 모듈형 벽·바닥·문
3. 플레이어와 괴물 기본 모델·애니메이션
4. 핵심 미션 스테이션과 영구 단서
5. 정보성 SFX와 기본 VFX
6. 방별 색·표지·조명
7. 공용 프롭과 환경음
8. 결과·엔딩 연출
9. 장식과 추가 변형

레이아웃이 확정되기 전에 장식용 방 에셋을 대량 제작하지 않는다.
