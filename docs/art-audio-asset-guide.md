# 아트·오디오 에셋 가이드

> 문서 버전: 1.0  
> 목표: 작은 팀이 일관된 3D 탑뷰 연구소를 빠르게 제작하기 위한 아트 바이블과 에셋 목록

---

## 1. 시각 방향

### 1.1 스타일

- 스타일라이즈드 로우폴리 3D
- 캐릭터는 3등신 데포르메, 환경은 실제 스케일 (§1.4 참조)
- 단순한 형태와 읽기 쉬운 실루엣
- 사실적인 재질보다 방 기능과 위험의 가독성 우선
- 직접적 고어보다 혈흔, 붉은 경고등, 그림자와 소리로 공포 표현
- 카메라 거리에서 보이지 않는 작은 디테일은 제작하지 않음

### 1.2 핵심 대비

- 차가운 청록·청색 연구소 환경
- 따뜻한 주황 비상등
- 빌런 강화와 감염은 강한 적색
- 상호작용 가능 오브젝트는 약한 청록 발광

### 1.3 권장 팔레트

| 용도 | 색상 예시 |
| --- | --- |
| 배경 암부 | `#111820` |
| 금속 벽 | `#35434C` |
| 의료 백색 | `#C8D4D8` |
| 시스템 청록 | `#34C6C8` |
| 전력 노랑 | `#E7B84B` |
| 경고 주황 | `#E87532` |
| 감염 적색 | `#D63B42` |
| 빌런 자주 | `#8C4EC7` |

색상은 방향이며 최종 머티리얼과 조명에서 명도 대비를 확인한다.

### 1.4 캐릭터 비율 기준

참고 톤은 어몽어스 계열의 데포르메 캐주얼이다. 색상과 실루엣만으로 플레이어를 구분할 수 있어야
하고, 정체를 숨기는 게임이므로 캐릭터 개별 특징은 오히려 최소화한다.

| 항목 | 기준 |
| --- | --- |
| 직원 등신 | 3등신 (머리 1 : 몸 2) |
| 캐릭터 실제 높이 | 약 1.6m — 문·통로 수치는 그대로 유지 |
| 스켈레톤 | 휴머노이드 유지 |
| 괴물 톤 | 데포르메하지 않음 (§3.1 참조) |

3등신은 어몽어스의 2등신보다 한 단계 완만한 값이다. 이 프로젝트는 2D 탑다운이 아니라 50~60도
쿼터뷰이므로, 2등신까지 낮추면 머리에 가려 몸통과 진행 방향이 보이지 않는다. 3등신은 데포르메
인상을 주면서도 쿼터뷰에서 몸과 손 소켓이 읽히는 절충값이다.

휴머노이드 스켈레톤을 유지하는 이유는 기성 애니메이션 리타게팅을 계속 쓰기 위해서다. 이보다 더
낮은 등신에서는 팔다리가 몸통을 관통해 애니메이션 12종을 전부 직접 제작해야 한다.

캐릭터 높이를 1.6m로 두면 `map-level-design.md` §3의 문 폭 1.6~1.8m와 천장 3.2~3.8m를 바꾸지
않아도 된다. 머리가 커진 만큼 좁은 문에서 카메라 가림이 늘 수 있으므로 그레이박스에서 확인한다.

## 2. 캐릭터 에셋

### 2.1 직원

MVP는 기본 바디 한 개를 공유한다. 비율은 §1.4의 3등신 기준을 따른다.

- 실험복 또는 회사 작업복 실루엣을 데포르메로 단순화 (옷깃·주머니 등 큰 덩어리만)
- 상의·팔 밴드·신발 색상 6종
- 멀리서도 색상과 번호가 보이는 등·가슴 표식
- 머리가 크므로 쿼터뷰에서 표식이 가리지 않는 위치를 그레이박스에서 확인
- 손전등 장착 지점
- 배터리 운반 소켓
- 해독제 사용 손 소켓
- 유령용 단순 반투명 버전

#### 초기 폴리곤·텍스처 목표

| 항목 | 기준 |
| --- | --- |
| 본체 | 약 5k~12k triangles |
| 텍스처 | 1K 한 세트, 필요 시 2K로 상향 |
| 머티리얼 | 본체 1, 액세서리 최대 1 |
| 스켈레톤 | 휴머노이드 1개 공유 |
| LOD | MVP는 LOD0만, 성능 문제 시 LOD1 추가 |

데포르메로 형태가 단순해져 폴리곤과 텍스처 목표를 낮췄다. 디테일을 줄인 만큼 실루엣과 색 구분이
가독성을 책임진다.

### 2.2 직원 애니메이션

- Idle
- Walk
- Run
- Turn 또는 방향 블렌딩
- InteractShort
- InteractLoop
- CarryIdle
- CarryWalk
- Bitten
- UseAntidote
- Death
- GhostIdle/Move는 일반 이동 재사용 가능

Root Motion은 사용하지 않고 코드 이동과 애니메이터 파라미터를 사용한다.

## 3. 원숭이 괴물

### 3.1 형태

괴물은 직원과 달리 데포르메하지 않는다. 3등신 직원과 사실적 비율의 괴물을 한 화면에 두는 톤
충돌은 의도된 것이다. 귀여운 캐릭터 사이에 이질적인 포식자가 있을 때 공포가 더 커지며, 탑뷰에서
플레이어와 위험을 즉시 구분하게 해준다.

- 일반 원숭이보다 길고 불균형한 팔
- 직원보다 낮고 옆으로 넓은 실루엣 — 등신을 맞추지 않는다
- 낮은 자세에서도 탑뷰 실루엣이 직원과 명확히 다름
- 붉은 눈 또는 목 주변 RX-9 흔적
- 직접적인 장기 노출보다 변형된 피부와 털 표현
- 단계가 올라가도 모델 교체보다 머티리얼·VFX 강도 변화 사용

톤 충돌이 공포가 아니라 어색함으로 읽히면, 괴물을 데포르메하는 대신 조명·VFX·사운드를 먼저
조정한다. 두 방향을 섞으면 양쪽 다 약해진다.

### 3.2 기술 기준

| 항목 | 기준 |
| --- | --- |
| 본체 | 약 15k~30k triangles |
| 텍스처 | 2K 한 세트 |
| 머티리얼 | 몸 1, 눈·발광 1 |
| 스켈레톤 | 1개 |
| 콜라이더 | 이동 캡슐 + 물기 판정 영역 |

### 3.3 애니메이션

- Idle
- Walk
- FastRun
- Listen
- Search
- Turn
- Bite
- Recover
- CageExit

물기 애니메이션은 판정 프레임을 Animation Event 자체로 결정하지 않고 서버 타이밍 데이터와 맞춘다.

## 6. 머티리얼과 텍스처

- URP Lit 기반을 기본으로 한다.
- 불필요한 투명 머티리얼을 줄인다.
- 환경은 타일러블 금속, 플라스틱, 고무, 유리 재질을 공유한다.
- 작은 프롭은 아틀라스를 사용한다.
- 방 구분은 별도 모델보다 머티리얼 색, 표지, 데칼로 해결한다.
- 탑뷰에서 읽히지 않는 4K 텍스처는 사용하지 않는다.
- 원본 작업 파일과 Unity용 출력 파일을 분리한다.

### 권장 출력

- 모델: FBX
- 텍스처: PNG 또는 TGA
- 일반 맵: Linear import
- 컬러·UI: sRGB import
- 오디오 원본: WAV
- 런타임 압축: Unity Import Settings에서 용도별 적용

## 8. 조명과 후처리

## 9. UI 아트

- 의료 단말과 비상 시스템을 연상시키는 직사각형 패널
- 본문은 한글 가독성 우선
- 아이콘은 24px에서도 형태가 구분돼야 함
- 모든 플레이어 색상에 번호 또는 기호 병행
- 미션 UI는 월드 장비의 색과 형태를 이어받음
- 빌런 전용 UI는 자주·적색이지만 외부 캐릭터 연출은 정상 미션과 같음

UI 세부 화면과 상태는 `ui-ux-design.md`를 따른다.

## 10. 오디오 디자인 원칙

소리는 분위기뿐 아니라 실제 게임 정보다.

1. 괴물 반응을 일으키는 게임 소음과 분위기 소리를 구분한다.
2. 게임 소음은 발생 원인과 위치를 학습할 수 있어야 한다.
3. 괴물의 접근은 화면 밖에서도 판단 가능해야 한다.
4. 음악이 발소리, 경보와 감염 타이머를 가리지 않는다.
5. 중요한 소리는 방향 표시와 자막을 지원한다.

## 11. 오디오 믹서 구조

```text
Master
├── Music
├── Ambience
├── SFX
│   ├── Player
│   ├── Monster
│   ├── Mission
│   ├── World
│   └── Danger
└── UI
```

회의 중에는 월드 SFX와 Ambience를 낮추되 완전히 끄지 않고 정지된 연구소의 잔향을 약하게 남긴다. `Danger`와 UI는 별도 볼륨 조절을 제공하되 0으로 만들 경우 시각 경고가 반드시 켜져야 한다.

## 13. 공간 음향 규칙

- 괴물, 미션, 스피커, 문은 3D AudioSource를 사용한다.
- UI와 개인 감염 심장 박동은 2D로 재생한다.
- 벽 하나를 사이에 둔 소리는 저역 통과와 볼륨 감소를 적용할 수 있다.
- 실제 괴물 AI의 소음 반경과 플레이어가 듣는 오디오 감쇠는 별도 데이터지만 모순되지 않게 조정한다.
- 스피커 소리는 방 바깥에서도 방향을 찾을 수 있어야 한다.
- 같은 효과음이 반복될 때 피치와 샘플 변형으로 피로를 줄인다.

## 15. 외부 에셋 규칙

- 구매·무료 여부와 관계없이 상업적 사용 가능 여부를 확인한다.
- 원본 링크, 제작자, 라이선스, 수정 여부를 기록한다.
- 서로 다른 스타일의 에셋은 머티리얼과 비율을 통일한 뒤 사용한다.
- 외부 패키지 전체를 `Assets/_Project` 안으로 이동하지 않는다.
- 샘플 씬과 미사용 고해상도 파일은 프로젝트에 포함하지 않는다.
- 라이선스 전문 또는 고지 의무는 `THIRD_PARTY_NOTICES.md`에 남긴다.
