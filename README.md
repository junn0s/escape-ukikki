# Escape Ukikki (원숭이 괴물 탈출 게임)

> 정전된 생명공학 연구소에서 5명의 생존자가 소리를 추적하는 원숭이 괴물을 피해 시설을 복구한다.
> 그중 한 명은 괴물을 만든 과학자이며, 직원으로 위장한 채 괴물을 강화하고 사람들을 죽음으로 유도한다.

핵심 질문은 "누가 공격했는가"가 아니라 **"누가 괴물이 공격할 상황을 만들었는가"** 이다.

| 항목 | 내용 |
| --- | --- |
| 장르 | 온라인 비대칭 소셜 디덕션 + 협동 탈출 + PvE 추격 |
| 인원 | 6명 고정 (생존자 5 + 빌런 1) |
| 한 판 | 탐색 15분, 회의 중 시간 정지 |
| 엔진 | Unity 6.3 LTS URP / C# |
| 네트워크 | Netcode for GameObjects + Relay (플레이어 1명이 호스트) |
| 플랫폼 | Windows PC, 3D 탑뷰/쿼터뷰 |
| 현재 단계 | M1 로컬 버티컬 슬라이스 진행 중 |

## 시작하기

`docs/`가 이 프로젝트의 기준이다. 코드보다 문서가 먼저다.

1. [최종 게임 기획서](docs/game-design-document.md) — 게임이 무엇인지
2. [MVP 범위](docs/mvp-scope.md) — 해커톤에 넣을 것과 뺄 것
3. 이후는 역할에 따라 → [문서 목록과 읽기 순서](docs/README.md)

작업 기록은 [docs/devlog.md](docs/devlog.md)에 남긴다.

Unity Hub에서 저장소의 `game/` 폴더를 프로젝트로 추가한다. 에디터 버전은
`6000.3.20f1`이며, 현재 첫 플레이어블은
`game/Assets/_Project/Scenes/10_Laboratory.unity`를 열어 확인할 수 있다.

현재 구현 범위와 다음 작업은 [개발 현황](docs/development-status.md)에 정리한다.

## 규칙 요약

- 문서가 충돌하면 상위 문서를 따른다. 우선순위는 [docs/README.md](docs/README.md)에 있다.
- **밸런스 수치**(쿨타임, 강화 단계 등)는 자유롭게 조정한다. 단 문서와 데이터를 함께 고친다.
- **핵심 규칙**(6인 구성, 역할, 승리 조건, 핵심 루프)은 기획서 합의 없이 바꾸지 않는다.
- 반영 순서는 항상 문서 → 데이터 → 테스트 → 코드.
- 브랜치·커밋 규칙은 [프로젝트 구조](docs/project-structure.md) §10.4를 따른다.
- 파일명에 `최종`, `진짜최종`, `수정본`을 붙이지 않는다. Git 이력과 문서 버전으로 관리한다.

## AI 도구를 함께 쓴다면

`AGENTS.md`, `CLAUDE.md`, `.claude/`는 개인 설정이 아니라 **팀 공용 규칙**이다.
이 파일들이 있으면 AI가 위 규칙을 매번 설명하지 않아도 알아서 지킨다. 그대로 두고,
바꿔야 하면 팀과 합의한 뒤 커밋한다.

Codex 등 다른 도구를 쓰면 `AGENTS.md`가 자동으로 적용된다.
`.claude/rules/`와 `.claude/skills/`는 도구 없이 체크리스트로 읽어도 된다.
