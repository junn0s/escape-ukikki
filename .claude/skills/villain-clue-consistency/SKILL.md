## Purpose
빌런 추리 단서가 기획서 규칙(영구 단서)을 지키며 구현되는지 확인한다.

## Use When
- 붉은 연기(감지범위 강화 흔적), 바닥 주사기(감염시간 감소 흔적) 등 단서 오브젝트를 구현할 때
- CCTV, 서버 로그 열람 기능을 구현할 때
- 스피커 사용 흔적(어느 방에서 켜졌는지) 관련 코드를 다룰 때

## Inputs
- `docs/game-design-document.md` 추리 단서 절
- `docs/system-design-document.md` 단서 상태 관리 방식

## Process
1. 단서가 한 번 발생하면 라운드 종료까지 사라지지 않는지 확인한다 (타이머로 자동 제거되지 않아야 함).
2. 단서가 발생한 정확한 위치(방)와 실제 원인(어느 강화 행동)이 논리적으로 일치하는지 확인한다.
3. 단서 정보가 클라이언트 전체에 과도하게 브로드캐스트되어 스포일러가 되지 않는지 확인한다
   (방에 들어가야 보이는지, 서버 로그처럼 열람 행동이 필요한지).

## Outputs
- 단서별 지속성·발생 조건 점검 결과

## Common Failure Modes
- 단서 오브젝트에 자동 소멸 타이머가 붙어있는 경우
- 단서 발생 위치와 실제 강화 행동 위치가 어긋나는 경우

## Related Agents
- `game-developer`, `code-reviewer`
