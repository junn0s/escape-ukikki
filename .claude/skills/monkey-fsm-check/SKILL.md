## Purpose
원숭이 AI의 상태머신·소리 반응·감지 로직이 기획서(GDD, SDD)의 강화 3단계 수치와
어긋나지 않도록 확인한다.

## Use When
- 원숭이 AI 순찰/추적/복귀 상태머신 코드를 새로 작성하거나 수정할 때
- 소리 우선순위, 이동속도 가속(6초, 1.5배) 로직을 다룰 때
- 강화 단계(감지범위, 마릿수, 해독제 제한시간) 관련 값을 다룰 때

## Inputs
- `docs/game-design-document.md`의 원숭이 AI 관련 절
- `docs/system-design-document.md`의 상태머신 정의
- `docs/balance-and-telemetry.md`의 강화 3단계 수치표
- 수정 대상 C# 스크립트 (예: `MonsterFsm.cs`, `MonsterSenses.cs`)

## Process
1. 기획서의 강화 3단계 표를 다시 확인한다.

   | 강화 항목 | 1단계 | 2단계 | 3단계(최종) |
   | --- | --- | --- | --- |
   | 감지 범위 | 0.5m | 1m | 2m |
   | 괴물 마릿수 | 4마리 | 6마리 | 8마리 |
   | 해독제 사용 제한시간 | 1분 30초 | 1분 | 30초 |

2. 코드에서 이 값들이 하드코딩되어 있지 않고 `SO_MonsterTier` 계열 ScriptableObject를
   참조하는지 확인한다.
3. 소리 반응 시 6초간 이동속도가 플레이어 이동속도의 1.5배로 상승하는지 확인한다.
4. 여러 소리가 동시에 발생할 때 "가장 가까운 소리"를 우선하는지 확인한다 (system-design-document.md 기준).
5. 값이 기획서와 다르면, 임의로 코드를 고치지 말고 사용자에게 먼저 확인한다.

## Outputs
- 기획서 수치와 코드 값의 일치/불일치 여부
- 불일치 시 구체적인 파일·라인과 수정 제안

## Quality Bar
- 강화 3단계 수치 중 하나라도 하드코딩되어 있으면 통과로 보지 않는다.
- 기획서와 다른 값을 발견했는데 보고 없이 넘어가면 안 된다.

## Common Failure Modes
- 감지 범위·마릿수 값을 스크립트에 매직 넘버로 직접 적어둔 경우
- "가장 가까운 소리" 대신 "가장 최근 소리"로 잘못 구현한 경우
- 강화 단계 전환 시 기존에 생성된 괴물 인스턴스에 새 수치가 반영되지 않는 경우

## Related Agents
- `game-developer` (구현), `debugger` (동작 이상 시), `qa-expert` (테스트 케이스 설계)

## Notes
- 이 스킬은 코드를 대신 작성하지 않는다. 기획서 대비 정합성만 검증하고, 실제 구현은
  `game-developer` 서브에이전트나 일반 대화로 진행한다.
