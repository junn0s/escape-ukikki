# 기획·설계 문서 수정 규칙 (docs/README.md "변경 절차" 기준)

## 수정 순서
문서를 고칠 때는 아래 순서를 지킨다. 하위 문서만 고치고 상위 문서를 방치하지 않는다.

1. 변경 이유와 영향 범위를 확인한다.
2. GDD의 확정 규칙 변경인지, 밸런스 값 변경인지 구분한다.
   - 핵심 규칙(팀 구성/역할/승리 구조/핵심 루프) 변경이면 사용자 승인 없이 진행하지 않는다.
3. 최상위 문서를 먼저 수정한다 (문서 우선순위는 `AGENTS.md` 참조).
4. 관련 설계서와 QA 검증 항목을 함께 수정한다.
5. 구현 코드와 ScriptableObject 값을 마지막에 반영한다.

## 주의
- 각 문서 상단의 `문서 버전`과 `기준 GDD` 헤더를 확인한다. 확정 규칙을 바꿨다면 GDD 버전을 올린다.
- 문서 간 수치가 중복 서술된 곳(GDD ↔ 밸런스 문서 ↔ SDD)은 한쪽만 고치지 않는다.
- 밸런스 표를 수정하면 `balance-scriptableobject-sync` 스킬로 SO 필드와의 정합성을 확인한다.
- 문서 파일명에 "최종", "진짜최종", "수정본" 등을 붙이지 않는다.
- `docs/devlog.md`는 예외다. 사후 기록용이므로 위 절차 없이 맨 아래에 추가만 한다.
